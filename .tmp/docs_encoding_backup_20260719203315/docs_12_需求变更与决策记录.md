## 2026-07-18 Round 2 决策：考试状态机与时间窗口强一致

- 背景：用户要求进入 Round 2，收敛考试状态机与答题时间窗口，避免前端可进入但后端未校验、重复交卷、多端草稿覆盖等问题。
- 决策：后端考试状态新增 `GRADING`，并将 `SCHEDULED / ONGOING / ENDED` 定义为时间驱动状态，`GRADING / SCORES_PUBLISHED` 定义为业务锁定状态。
- 决策：答卷草稿保存新增 `expectedVersion`，作为 P0 乐观并发控制；旧客户端未传时暂兼容。
- 决策：保存草稿与提交答卷均必须落在 `[startAt, endAt)`，交卷接口具备幂等语义。
- 决策：前端新增 `ENDED` 展示状态，不再把后端 `ENDED` 混同为 `GRADING`。
- 影响文档：04、08、11、12、14、OpenAPI 契约。
## 2026-07-18 Round 3 决策：超时自动交卷与缺考

- 背景：考试闭环必须处理到点未手动提交、到点完全未作答两类现场高频问题。
- 决策：后端统一以考试 `endAt` 作为强一致边界，定时任务与读请求均可触发生命周期刷新。
- 规则：`DRAFT + version > 0` 到点自动提交并创建批改任务；`DRAFT + version == 0` 到点标记 `ABSENT` 且不创建批改任务。
- 兼容性：由于创建批改任务后答卷可能立即进入 `GRADING`，前端和 Smoke 将 `SUBMITTED/GRADING/GRADED` 均视为已提交类终态。
- 数据库：通过 Flyway V11 增加 `ABSENT` 约束与 `answer_sheet(exam_id, status)` 索引。

## ADR-R4-REVIEW-ARTIFACT：复盘、AI 讲评稿与导出真实化

- 日期：2026-07-18
- 背景：考试闭环已具备组卷、考试、答题、批改、成绩发布能力，需要将复盘分析从前端 Mock 派生升级为后端真实数据，并形成可归档产物。
- 决策：P0 后端使用确定性模板生成 AI 讲评稿，避免外部模型网络不稳定影响 Smoke；同时保留 `provider`、`prompt_snapshot`、`confidence` 和状态机，后续可平滑接入 Kimi。
- 决策：导出产物优先落地 MinIO，数据库仅保存元数据、校验值和对象路径，不把大文件写入 PostgreSQL。
- 影响：前端复盘页默认在 `VITE_USE_MOCK=false` 时调用真实接口；后端运行 Smoke 需确保 MinIO 配置可用。
## 2026-07-18 决策：考试闭环复验与中文编码质量门禁

- 背景：教师/学生考试闭环 Smoke 在复盘与 AI 讲评阶段暴露中文字符串编码破损风险，可能引发运行态 500 或导出产物乱码。
- 决策：所有新增/重写 Java、Vue、TS、Markdown 文件必须使用 UTF-8；PowerShell 写文件时优先使用 `System.Text.UTF8Encoding(false)` 或等价无 BOM 写入方式。
- 处理：已重写 ReviewService、KimiLectureDraftProvider、LocalTemplateLectureDraftProvider 的中文内容；后端测试、前端构建、账号 Smoke、考试闭环 Smoke、AI 异步下载 Smoke 均通过。
- 后续：真实 Kimi Provider 的密钥只允许通过运行时环境变量注入，不写入代码、文档或仓库配置。
### 2026-07-19：AI 出题 Provider 去 Kimi 绑定与中文输出硬化

- 背景：AI 出题审核页出现英文题目，且题目生成链路不应绑定单一 Kimi Provider。
