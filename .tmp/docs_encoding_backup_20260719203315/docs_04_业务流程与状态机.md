## Round 2：考试状态机与时间窗口强一致（2026-07-18）

本轮将后端真实考试状态统一为：

```text
DRAFT -> SCHEDULED -> ONGOING -> ENDED -> GRADING -> SCORES_PUBLISHED
```

关键约束：

- `SCHEDULED / ONGOING / ENDED` 为时间驱动状态：读取考试列表、详情、学生考试列表时，后端按 `startAt <= now < endAt` 自动推进到 `ONGOING`，超过 `endAt` 自动推进到 `ENDED`。
- `GRADING / SCORES_PUBLISHED` 为业务锁定状态，不再被时间刷新回退。
- 学生保存草稿、提交答卷只允许发生在考试答题窗口 `[startAt, endAt)` 且考试状态为 `ONGOING` 时。
- 草稿保存支持 `expectedVersion` 乐观版本校验；客户端版本与服务端 `answer_sheet.version` 不一致时返回 `409 CONFLICT`，防止多端覆盖。
- 交卷接口幂等：`SUBMITTED / GRADING / GRADED` 状态下重复提交不重复创建批改任务，返回当前答卷状态。
- 批改任务创建后，如果考试已经结束，或该考试已无 `DRAFT` 答卷，则考试进入 `GRADING`。
- 成绩发布只允许存在已复核批改任务时执行；若仍存在未 `REVIEWED` 批改任务，发布返回 `409 CONFLICT`。

前端约束：

- 后端 `ONGOING` 映射为前端 `IN_PROGRESS`，后端 `ENDED` 映射为前端 `ENDED`，后端 `SCORES_PUBLISHED` 映射为前端 `PUBLISHED`。
- 学生端只有 `IN_PROGRESS` 可以答题；`SCHEDULED / ENDED / GRADING / PUBLISHED` 均展示不可答题状态。
- 学生答题页保存/提交失败时必须展示后端错误信息，不能让按钮长期处于 loading。
## Round 3 补充：超时自动交卷与缺考状态机

### 触发时机

- 后端定时任务按 `mindmark.exam.lifecycle.finalize-fixed-delay-ms` 扫描已到 `endAt` 的 `SCHEDULED`、`ONGOING`、`ENDED` 考试。
- 教师/学生读取考试列表、考试详情、答卷详情时，也会触发同一套生命周期刷新，避免只依赖定时任务。

### 答卷终态规则

| 条件 | 答卷状态 | 后续动作 |
| --- | --- | --- |
| `DRAFT` 且 `version > 0`，当前时间已到 `endAt` | `SUBMITTED`，随后可进入 `GRADING` | `submittedAt = min(now, endAt)`，创建批改任务 |
| `DRAFT` 且 `version == 0`，当前时间已到 `endAt` | `ABSENT` | 不创建批改任务，学生端展示缺考 |
| `SUBMITTED` / `GRADING` / `GRADED` | 保持原状态 | 交卷与批改流程保持幂等 |

### 考试状态推进

- 考试结束时如所有有效答卷均已提交或进入批改，考试可进入 `GRADING`。
- `GRADING`、`SCORES_PUBLISHED` 不因时间刷新回退。
- 超时后的保存草稿与交卷请求不再制造 500；返回服务端最终答卷状态。
## 2026-07-19 流程补充：答题防作弊与 AI 出题写入状态

### 学生答题安全流程

```text
进入答题页 -> 加载考试/答卷 -> 展示倒计时 -> 学生点击进入全屏 -> 允许作答
  -> 保存草稿/提交答卷仍受后端时间窗口校验
  -> 倒计时归零或异常次数达到阈值 -> 自动交卷
```

异常事件计数范围：页面隐藏、窗口失焦、退出全屏。当前 P0 阈值为 3 次；未处于全屏时前端禁用作答、保存和提交，以避免学生在不安全状态继续答题。

### AI 题目生成入库流程

```text
教师打开 AI 出题审核页
  -> 选择 OpenAI / Anthropic Provider，并读取当前教师个人 Key 脱敏配置
  -> 选择课程、题型、五级难度、知识点与生成要求
  -> LangGraph: validate_input -> resolve_course -> generate_with_ai -> persist_questions
  -> 服务端校验题干、选项、解析、评分点为中文内容
  -> 写入 question(source=AI, status=PENDING_REVIEW)
  -> 教师在审核列表中复核后再进入正式题库使用
```

约束：Provider API Key 解析顺序为教师个人配置优先、对应全局环境变量兜底；链路失败不得产生半成品无课程题目。
