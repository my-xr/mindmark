# 19 后端接口契约准备

> 文档状态：已重建为 UTF-8。更新时间：2026-07-19。  
> 本文描述前端真实接口联调所依赖的后端契约，OpenAPI 以 `apps/mindmark-server/openapi/mindmark-api.yaml` 为准。

## 1. 服务基础

- 后端应用：`apps/mindmark-server`
- API 前缀：`/api/v1`
- 数据库：PostgreSQL，开发库 `mindmark`
- 缓存：Redis `6379`
- 对象存储：MinIO bucket `mindmark-artifacts`
- 鉴权：Sa-Token，`Authorization: Bearer <token>`

## 2. 统一响应

```json
{
  "success": true,
  "code": "OK",
  "message": "ok",
  "data": {}
}
```

错误响应必须包含稳定 `code` 和可读 `message`。

## 4. 题库契约

### 查询题目

`GET /api/v1/questions`

查询参数：

- `page/pageSize`
- `keyword`
- `courseId`
- `type`
- `difficulty`
- `status`
- `source`

### 创建题目

`POST /api/v1/questions`

核心字段：

```json
{
  "courseId": "course-frontend-001",
  "title": "题干",
  "type": "SINGLE_CHOICE",
  "difficulty": "MEDIUM",
  "score": 5,
  "answer": "A",
  "analysis": "解析",
  "options": [{ "key": "A", "content": "选项" }],
  "scoringPoints": [],
  "knowledgePoints": ["组件通信"]
}
```

### 批量导入题目

`POST /api/v1/questions/import`

- 重复判断建议使用：课程 + 题型 + 标题。
- 返回 `importedCount/skippedCount/errors`。

### AI 题目审核

`POST /api/v1/questions/{id}/review`

请求：

```json
{ "action": "ACCEPTED" }
```

`action` 可为：`ACCEPTED/EDITED_ACCEPTED/REJECTED`。

## 5. AI Provider 与 LangGraph 出题

### 查询 Provider 配置

`GET /api/v1/ai/provider-settings?provider=OPENAI|ANTHROPIC`

响应：

```json
{
  "provider": "OPENAI",
  "providerLabel": "OpenAI",
  "configured": true,
  "keyPreview": "****abcd12",
  "updatedAt": "2026-07-19T20:00:00"
}
```

### 保存 Provider Key

`PUT /api/v1/ai/provider-settings`

```json
{
  "provider": "OPENAI",
  "apiKey": "只在请求中出现，后端加密保存，不返回明文"
}
```

### 生成 AI 题目

`POST /api/v1/ai/questions/generate`

```json
{
  "courseId": "course-frontend-001",
  "provider": "OPENAI",
  "prompt": "围绕 Vue 组件通信生成题目",
  "questionType": "SINGLE_CHOICE",
  "difficulty": "MEDIUM",
  "count": 3,
  "knowledgePoint": "Vue 组件通信",
  "requirement": "题干清晰，选项区分度高，解析必须使用中文。"
}
```

规则：

- Provider 仅支持 `OPENAI/ANTHROPIC`。
- `KIMI` 旧路径仅兼容历史前端，不作为新入口。
- 后端通过 LangGraph 节点：`validate_input -> resolve_course -> generate_with_ai -> persist_questions`。
- 生成结果写入 `PENDING_REVIEW`，必须人工审核后才能成为 `ACTIVE`。

## 批改与成绩分页契约落地（2026-07-21）

本轮补齐批改中心与成绩中心分页契约，前端已切换为真实分页接口：

| 场景 | 接口 | 说明 |
| --- | --- | --- |
| 批改中心-答卷队列 | `GET /api/v1/grading-tasks?page=1&pageSize=8` | 返回 `PageResponse<GradingTaskResponse>`；可选 `examId` 过滤考试。 |
| 批改中心-答卷题目 | `GET /api/v1/grading-tasks/{gradingTaskId}/items?page=1&pageSize=10` | 返回 `PageResponse<GradingItemResponse>`；用于 30-50 题答卷逐页批改。 |
| 成绩中心-成绩批次 | `GET /api/v1/score-summaries?page=1&pageSize=8` | 返回 `PageResponse<ExamScoreSummaryResponse>`；用于考试成绩批次分页。 |
| 成绩中心-学生成绩明细 | `GET /api/v1/exams/{examId}/score-reports?page=1&pageSize=10` | 返回 `PageResponse<ScoreSummaryItemResponse>`；切换考试后重置页码。 |

验收要求：
- 批改中心翻页不丢失当前页已调整分数；提交复核时汇总全量题目，避免只提交当前页。
- 切换答卷、切换考试、切换每页条数时自动重置或校正子分页。
- 后端统一返回 `totalPages/hasPrevious/hasNext`，前端兼容展示并以 `total/page/pageSize` 驱动分页。
- 当前实现已完成后端分页契约和前端真实接口化；后续性能优化可继续将权限过滤后的内存分页收敛为 repository 层数据库分页与 count 查询。

## 分页数据库级优化与权限过滤下沉（2026-07-21）

本轮将批改中心与成绩中心的分页从“接口返回 PageResponse + 服务层内存切片”升级为 Repository/Pageable 数据库级分页：

- `GET /api/v1/grading-tasks?page&pageSize`：使用 `GradingTaskRepository.pageVisibleTasks(...)`，在 JPQL 层完成考试班级权限过滤与 `count` 统计；教师/助教必须拥有考试全部班级权限，管理员可查看全部。
- `GET /api/v1/grading-tasks/{gradingTaskId}/items?page&pageSize`：使用 `GradingItemRepository.findByGradingTaskIdOrderByCreatedAtAsc(...)` 逐页读取批改题目，只查询当前页对应答题项，避免 30-50 题答卷一次性加载。
- `GET /api/v1/score-summaries?page&pageSize`：使用 `ExamRepository.pageVisibleExamsWithGradingTasks(...)` 只分页查询有批改任务的可见考试。
- `GET /api/v1/exams/{examId}/score-reports?page&pageSize`：使用 `GradingTaskRepository.findByExamIdAndStatusAndFinalScoreIsNotNullOrderByFinalScoreDescUpdatedAtAsc(...)` 按分数降序数据库分页，页内排名按全局偏移计算。

分页兜底规则：`page` 从 1 开始；`pageSize` 最大 100；当请求页超过最后一页时，后端会自动回落到最后一页，避免前端出现空页。自动化验收新增 `scripts/api-smoke/run-pagination-contract-smoke.ps1`，并已接入 `scripts/run-local-acceptance.ps1`。

## Dashboard 首屏聚合契约与分页性能验证（2026-07-21）

```json

```

### 实现约束

- 前端真实接口模式必须只调用 `GET /api/v1/teacher/dashboard` 渲染教师工作台首屏；Mock 模式可保留本地多接口聚合用于演示。
- 后端聚合必须使用 Repository 层分页与 count 查询，不允许 `findAll` 后在 Java Stream 中完成全量过滤和截取。
- 管理员、教师、助教的班级权限过滤必须在查询层体现；无可见班级时返回空集合与 0 指标。
- 聚合接口已写入 OpenAPI，自动化 Smoke 为 `scripts/api-smoke/run-dashboard-smoke.ps1`。

### 性能验证脚本

- `scripts/db/run-pagination-explain.ps1`：优先使用 `psql` 执行 EXPLAIN。
- `scripts/db/run-pagination-explain-jdbc.ps1`：本机没有 `psql` 时使用 PostgreSQL JDBC driver 执行同等 EXPLAIN 采样。
- 默认输出：`.tmp/pagination-explain-report.txt`。

本轮本地验证结果：Dashboard Smoke 与分页契约 Smoke 通过；当前开发数据量下高频分页 SQL 执行时间均在亚毫秒级，Dashboard 进行中考试查询已命中 `idx_exam_status_updated`。
