# 24 真实浏览器视觉与批量数据巡检记录

> 文档状态：已修复为 UTF-8 with BOM。最后更新：2026-09-20。  
> 目标：记录真实后端、真实数据库和真实浏览器下的页面级验收结果，不以 Mock 页面通过代替真实业务验收。

## 1. 验收环境

- 后端：Spring Boot，`http://localhost:8080`
- 前端：Vite + Playwright，真实接口模式 `VITE_USE_MOCK=false`
- 数据库：PostgreSQL，数据库名 `mindmark`，端口 `5432`
- Redis：`6379`
- MinIO：`9000/9001`，bucket `mindmark-artifacts`
- 浏览器项目：Playwright `teacher-chrome`
- AI Provider：仅使用本地个人配置或环境变量，不把 API Key 写入代码、日志、文档或验收截图。

## 2. 本轮验收范围

本轮重点不是继续扩展功能，而是验证已经完成的真实闭环：

1. 教师端核心页面能否在真实 API 下加载、筛选、分页和完成主操作。
2. 学生端登录、考试时间状态、全屏答题、切屏审计、保存草稿、交卷和超时边界是否可用。
3. 管理端账号治理和权限边界是否可用。
4. AI Provider 连接失败时是否给出中文、可操作且不泄露 Key 的提示。
5. 批量学生数据下分页契约是否真实生效，而不是前端假分页。

## 3. 自动化验收资产

### 3.1 教师端页面巡检

```powershell
pnpm web:e2e:teacher
```

覆盖教师工作台、题库管理、AI 出题审核、试卷与组卷、考试管理、学生名单与账号、批改中心、成绩中心、考试复盘和个人配置等页面。

### 3.2 学生端安全闭环

```powershell
pnpm web:e2e:student
pnpm web:e2e:student-boundary
```

覆盖登录竞态、考试进入、全屏入口、切屏/失焦事件、保存草稿、交卷、自动交卷和结束边界。

### 3.3 管理端与 Provider 失败场景

```powershell
pnpm web:e2e:admin
pnpm web:e2e:ai-failure
```

重点验证账号治理、权限页面和错误 Provider 地址下的中文提示、错误关闭和 Key 脱敏。

### 3.4 批量数据 API Smoke

```powershell
pnpm server:smoke:bulk
```

脚本创建临时课程、班级、学生、题目、试卷、考试和答卷，并检查 `items`、`total`、`page`、`pageSize`、`totalPages`、`hasPrevious`、`hasNext` 等分页字段。

## 5. 本轮问题与修复记录

### 5.1 教师端选择器误匹配

状态筛选的自动化选择器曾误匹配课程下拉框，已改为基于字段语义和页面区域定位，避免测试通过错误控件。

### 5.2 学生端登录竞态

学生登录后同时存在登录页和学生布局渲染的短暂窗口，测试改为等待明确的登录完成状态，避免固定等待时间造成假阴性。

### 5.3 学生端测试数据固定 ID 风险

安全测试不再依赖固定 `paper-001`，而是在测试中动态创建课程、题目和试卷，确保测试验证的是当前接口链路。

### 5.4 全屏入口重复定位

答题页存在顶部全屏入口和遮罩入口，自动化测试固定点击顶部主入口；页面仍保留遮罩中的唯一主操作，真实用户可以从任一明确入口进入全屏。

### 5.5 自动交卷边界竞态

自动交卷发生瞬间不再继续点击保存按钮，测试改为等待提交状态并验证答卷最终状态，避免把浏览器事件竞态误判为业务失败。

### 5.6 错误信息中文化

退出登录、修改密码、资源不存在、无权限、服务器错误和 AI Provider 失败均统一经过前端错误映射；页面不应展示 `MM-xxx-xxx`、`Internal server error`、堆栈或完整 API Key。

## 6. 页面级视觉验收重点

### 6.1 教师端

- 顶部导航不重复展示页面标题和副标题。
- 列表页以整行列表为主，详情页独立展开，不使用拥挤的左右窄栏。
- 表格列宽稳定，长题干、长课程名和长考试名使用省略或合理换行。
- 操作列固定在右侧，按钮统一使用 `AppActionButton` 或 Ant Design Vue 组件。
- 有大量数据的页面必须显示真实分页；筛选、切换考试和返回列表时重置明细页码。
- 空状态、加载状态、错误状态和成功反馈均可关闭或不会阻塞后续操作。

### 6.2 学生答题页

- 试题区和答题卡是首要内容，考试无关说明移入须知或可折叠区域。
- 倒计时固定在顶部右侧，全屏入口放在保存状态附近。
- 未进入全屏时，试题和答题卡使用遮罩锁定，并明确提示必须全屏作答。
- 答题卡按单选、多选、判断、填空、简答、编程等题型分组。
- 返回考试中心需要二次确认，交卷按钮始终可见且不被底部内容遮挡。

## 7. 当前限制与未完成项

1. 反复运行 Smoke/E2E 会创建临时业务数据，当前本地数据库仍需要按运行批次清理；不能用 `TRUNCATE` 直接清空正式数据。
2. 分页查询中的集合 `@EntityGraph` 已移除，避免 Hibernate 对集合抓取分页自动退化为内存分页；分页 DTO 在事务内复制必要的班级 ID，避免关闭 Open Session 后触发懒加载异常。
3. 当前验收是本地单机业务验收，不等同于生产压测；上线前仍需做慢 SQL、连接池、Redis、MinIO 和反向代理压测。
4. 真实 AI 验收不得把密钥固化到脚本或文档，应通过教师个人配置或本地环境变量注入，并在验收后清理测试 Provider 配置。

## 10. 2026-09-20：分页运行态修复与真实 API 复验

### 发现的问题

- 重启到最新后端后，`GET /api/v1/exams?page=1&pageSize=2` 首次返回 `MM-500-001`。
- 根因不是数据库分页 SQL，而是分页查询移除集合抓取后，`ExamResponse` 仍持有 Hibernate 的懒加载 `classIds` 集合；HTTP 序列化发生在事务结束后，触发 `LazyInitializationException`。

### 修复

- `ExamResponseMapper` 在事务内使用 `List.copyOf(entity.getClassIds())` 创建 DTO 快照。
- 保持分页查询不抓取 `classIds`、`participants`、`answerSheets` 集合，避免恢复内存分页。
- 移除讲评稿、讲评任务和 AI 批改任务 `findFirst/findTop` 查询中的 `exam.classIds` 集合抓取，避免 `maxResults=1` 与集合抓取组合产生内存分页。
- 开启 `hibernate.query.fail_on_pagination_over_collection_fetch`，将同类问题在开发和验收阶段直接暴露为失败，而不是静默退化。
- 全局异常处理器增加服务端异常日志，保留对用户的中文安全提示，不输出敏感配置。
