# 01 产品定位与用户痛点

## 1. 产品定位

MindMark（明镜台）是面向院校、课程团队、教师和教学助理的智慧教考评一体化平台。当前阶段以考试系统闭环为核心，帮助教师用一个系统完成题库建设、AI 出题、组卷、开考、批改、成绩发布和复盘分析。

## 2. 目标用户

| 用户角色 | 主要目标 | 典型任务 |
| --- | --- | --- |
| 教师 | 高效完成考试全流程并掌握班级学习情况 | 维护题库、AI 生成题目、组卷、发布考试、复核 AI 批改、发布成绩、查看复盘 |
| TA / 助教 | 协助教师完成题库、批改和答疑 | 审核题目、处理主观题复核、汇总申诉、维护学生名单 |
| 学生 | 稳定参加考试并获得清晰反馈 | 参加考试、保存草稿、提交试卷、查看成绩、查看错题归因 |
| 管理员 | 管理组织、账号、权限和系统配置 | 维护角色权限、课程/班级、基础配置、审计查看 |

## 3. 核心痛点

### 3.1 教师侧痛点

1. 出题、组卷、批改分散在多个工具中，流程割裂。
2. 客观题可自动化，但简答题、编程题仍需要大量人工判断。
3. 题目缺少统一元数据，后续难以做知识点诊断和复盘分析。
4. 成绩发布后缺少班级层面、题目层面、知识点层面的解释。
5. AI 可以提效，但如果没有人工审核和可追溯机制，教师不敢直接使用。

### 3.2 学生侧痛点

1. 在线考试体验不稳定时会担心断线、草稿丢失或倒计时异常。
2. 成绩只有分数，缺少错因、知识点薄弱项和复习建议。
3. 申诉和查分流程不透明，沟通成本高。

### 3.3 管理侧痛点

1. 多角色权限容易混乱，学生数据隔离要求高。
2. 考试行为、批改调整、成绩发布需要审计留痕。
3. 后续接入 AI、Redis、PostgreSQL、RAG 时，需要清晰模块边界和扩展策略。

## 4. 产品价值主张

| 价值 | 说明 |
| --- | --- |
| 降本提效 | AI 辅助出题、批改和讲评，降低重复性工作量。 |
| 闭环管理 | 从题库到复盘形成完整链路，避免多个系统反复切换。 |
| 可信 AI | AI 先处理，人审兜底；所有关键结果可解释、可复核、可追溯。 |
| 数据沉淀 | 作答、成绩、知识点和错因数据沉淀为后续学生画像基础。 |
| 企业级可演进 | 权限、审计、异常、接口、数据模型和测试先行设计。 |

## 5. 当前 MVP 的核心用户旅程

### 5.1 教师旅程

```text
登录工作台 → 查看考试筹备概览 → 维护题库 / 使用 AI 生成题目 → 审核题目并入库 → 创建试卷与考试 → 发布考试 → 监控考试进度 → 查看自动批改与 AI 预批改结果 → 复核主观题 → 发布成绩 → 查看复盘分析与知识点诊断
```

### 5.2 学生旅程

```text
登录学生端 → 查看待参加考试 → 阅读考试须知 → 进入答题页面 → 自动保存草稿 / 标记题目 / 查看倒计时 → 提交试卷 → 等待批改 → 查看成绩、错题和反馈 → 必要时提交申诉
```

## 6. 产品体验关键词

清晰、稳定、可控、可解释、可扩展。涉及 AI、成绩、批改和考试安全的页面必须突出状态、依据、人工操作入口和风险提示。
