# 11 Test Acceptance and Quality Gates

> Status: rebuilt as UTF-8 without BOM on 2026-07-22.
> Purpose: define validation gates for MindMark frontend, backend, API contracts, database migrations, and exam closed-loop acceptance.

## 1. Mandatory gates before delivery

- Backend compile must pass.
- Key backend unit tests must pass.
- Frontend typecheck must pass.
- Frontend production build must pass.
- Database migrations must be repeatable through Flyway.
- API changes must be reflected in OpenAPI and related docs.
- New or changed user-facing flows must be manually smoke-tested with real backend APIs when possible.

## 2. Backend validation

Recommended commands:

```bash
mvn -f apps/mindmark-server/pom.xml -DskipTests compile
mvn -f apps/mindmark-server/pom.xml test
```

Minimum checks:

- Application starts against PostgreSQL database mindmark.
- Redis connection is healthy when cache/session features are enabled.
- MinIO connection is healthy when artifact export/download features are used.
- All new endpoints return the unified ApiResponse format.
- Errors are mapped to friendly business messages when possible.
- Permission checks are enforced with Sa-Token and role/resource boundaries.

## 3. Frontend validation

Recommended commands:

```bash
pnpm --filter mindmark-web typecheck
pnpm --filter mindmark-web build
```

Minimum checks:

- No TypeScript or Vue compile errors.
- Main teacher and student routes can be opened.
- Buttons, forms, tables, filters, drawers, and pagination use shared components or Ant Design components.
- Long text is ellipsized or wrapped according to page design.
- Empty, loading, error, and success states are visible and user-friendly.

## 4. Exam closed-loop smoke

Teacher side:

1. Login as teacher.
2. Manage courses and classes.
3. Import or create questions.
4. Assemble a 100-point paper.
5. Create and publish an exam.
6. Monitor answer queue and security events.
7. Trigger auto/AI grading and review scores.
8. Publish scores and review analysis.

Student side:

1. Login as student.
2. Enter assigned exam.
3. Confirm notice and start exam.
4. Answer objective and subjective questions.
5. Verify countdown, fullscreen request, and security event reporting.
6. Save draft and submit.
7. View published score and feedback.

## 5. Markdown question import acceptance

- The sample Markdown question bank parses 78 questions.
- First import writes 78 questions.
- Repeated import skips 78 duplicates.
- Knowledge points are saved as the selected course name.
- Imported questions appear in the paginated question bank list.
- Long stems do not break database write or frontend table layout.

## 6. Quality rules for future iterations

- Do not leave demo-only buttons on enterprise pages.
- Do not add unpaginated large lists.
- Do not introduce raw form controls when shared form components or Ant Design can be used.
- Do not bind AI logic to a single provider name.
- Do not store or print plaintext API keys.
- Do not leave garbled text, BOM, or replacement characters in source files or docs.

## 7. Production and security gates

Before a production deployment, run the environment contract and health check with the `prod` profile:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run-production-check.ps1 -BaseUrl http://localhost:8080
```

The command requires production environment variables and refuses local database, Redis, MinIO, default credentials, default AI encryption keys, exposed OpenAPI, or non-health Actuator endpoints. It never prints secret values.

For real role and data-scope acceptance, use independent accounts and explicit course IDs:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/api-smoke/run-authz-security-smoke.ps1 `
  -RequireIndependentRoles `
  -TeacherUsername <teacher> -TeacherPassword <password> `
  -TaUsername <ta> -TaPassword <password> `
  -StudentUsername <student> -StudentPassword <password> `
  -AssignedCourseId <assigned-course-id> -OutOfScopeCourseId <other-course-id>
```

The login limiter smoke can also verify recovery after a shortened test window:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/api-smoke/run-login-rate-limit-smoke.ps1 `
  -AttemptCount 11 -RecoveryWaitSeconds 60
```

Do not run destructive smoke cleanup as part of an ordinary quality gate. Review the dry-run report first; formal deletion additionally requires `-Execute -Force -BackupPath`.
