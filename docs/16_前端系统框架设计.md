# 16 前端系统框架设计

## 1. 目标

本文档定义 `apps/mindmark-web` 的前端系统框架。正式开发前，必须先按本文档建立目录、路由、布局、状态、服务层、Mock 层和质量约束。

## 2. 技术选型

| 类别 | 选型 | 说明 |
| --- | --- | --- |
| 构建工具 | Vite | Vue 3 标准开发体验，启动快。 |
| 框架 | Vue 3 | Composition API。 |
| 语言 | TypeScript | 开启严格类型检查。 |
| 路由 | Vue Router | 按门户和业务模块拆分路由。 |
| 状态管理 | Pinia | 管理用户、权限、考试答题临时状态等。 |
| UI 组件库 | Ant Design Vue | 适合企业后台、表格、表单、弹窗和工作台。 |
| 图表 | ECharts / vue-echarts | 用于成绩分布、知识点诊断、复盘分析。 |
| HTTP | Axios | 后续真实接口接入；Phase 0 可由 service 读取 Mock。 |
| 日期时间 | dayjs | 考试时间、倒计时、提交时间展示。 |
| 工具库 | VueUse | 倒计时、窗口状态、全屏、可见性等组合能力。 |
| 代码编辑 | Monaco Editor（后续按需） | 编程题作答和展示，Phase 0 可先用 textarea。 |
| 样式 | CSS Variables + CSS Modules / Less 按需 | 优先使用项目 token，后续再与 Ant Design Vue Token 对齐。 |
| 测试 | Vitest + Vue Test Utils（后续） | 单元和组件测试。 |

### 2.1 Ant Design Vue 使用策略

- 当前工程保留 `ant-design-vue` 依赖和 reset 样式，业务页面阶段按需引入具体组件。
- 不在 `main.ts` 全量 `app.use(Antd)` 注册完整组件库，避免首屏 bundle 过大。
- 通用业务组件（如 `StatusTag`、`PageHeader`、`EmptyState`）优先沉淀为项目组件，再按需组合 Ant Design Vue 表格、表单、弹窗。

## 5. 分层依赖规则

```text
views → components → composables → services → mock/types/constants/utils
```

约束：

- `views` 只负责页面编排，不堆业务算法和大段 Mock。
- `components` 不直接访问后端，除非是明确的数据容器组件。
- `services` 是页面读取数据的唯一入口。
- `mock` 不被页面直接引用，只被 service 或 mock adapter 使用。
- `types` 不依赖 `views`、`components`、`services`。
- `utils` 必须是纯函数或无框架副作用工具。

## 6. 状态管理设计

| Store | 职责 |
| --- | --- |
| `useAuthStore` | 登录用户、角色、权限、token mock。 |
| `useAppStore` | 主题、侧边栏、全局加载状态。 |
| `useExamTakingStore` | 学生答题过程中的当前题、草稿保存状态、倒计时快照。 |
| `useNotificationStore` | 站内消息和未读数。 |

原则：

- 列表查询结果优先放页面局部状态，不滥用全局 store。
- 答题过程状态可以放 store，但提交和保存必须通过 service 抽象。
- 后续接入真实后端时，store 不直接拼接 API URL。

## 9. 页面文件约束

- `views` 单文件建议不超过 400 行，超过必须拆分。
- 表单逻辑超过 80 行时，抽到 composable。
- 表格列定义复杂时，抽到单独配置文件或 composable。
- 题型渲染必须组件化，不能在答题页里写大量 `v-if`。

## 11. 权限与菜单

- 菜单由路由元信息或统一菜单配置生成。
- 按角色过滤菜单和按钮。
- 页面级无权限跳转 `403`。
- 操作级权限通过 `v-permission` 或 composable 控制，后续实现。

## 12. 构建与性能约束

- Vite 构建需配置基础 vendor chunk，避免所有依赖进入入口 chunk。
- 企业级组件库、图表库、代码编辑器均按需引入。
- 学生答题页应尽量降低运行时依赖，优先保证稳定性和保存状态反馈。
- 任何新增大依赖必须说明用途，并在迭代复盘中记录 bundle 影响。

## 14. Iteration 11：Service 层 Mock/真实接口双模式

### 14.1 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `VITE_USE_MOCK` | 未设置，等价于启用 Mock | 仅当值为字符串 `false` 时关闭 Mock 并调用真实后端。 |
| `VITE_API_BASE_URL` | `/api` | Axios baseURL。开发态建议保持 `/api`，由 Vite proxy 转发。 |
| `VITE_API_TIMEOUT_MS` | `10000` | HTTP 请求超时时间。 |
| `VITE_API_PROXY_TARGET` | `http://localhost:8080` | Vite dev server `/api` 代理目标。 |

真实接口联调示例：

```powershell
$env:VITE_USE_MOCK="false"
$env:VITE_API_PROXY_TARGET="http://localhost:8080"
pnpm web:dev
```

### 14.2 Service 设计约束

- 页面层继续只调用 `services/*`，不得直接拼接 `/api/v1/**` URL。
- Mock 与真实接口切换必须在 service 层完成，不允许在 Vue 页面中写 `VITE_USE_MOCK` 分支。
- 真实接口统一通过 `services/api/httpClient.ts` 的 `apiClient` 访问，并解包后端 `ApiResponse<T>`。
- 后端分页统一适配为前端可消费的数组或页面所需结构，避免页面直接依赖后端分页结构。
- 后端字段暂缺时，可以在 service 层做明确降级，但必须在迭代复盘中记录并进入下一轮契约补齐计划。

### 14.3 已切换真实接口的 Service

| Service | 真实接口覆盖范围 | 备注 |
| --- | --- | --- |
| `questionService` | 题库列表筛选 | 读取 `GET /api/v1/questions`。 |
| `paperService` | 试卷列表、添加题目、移除题目 | 详情与状态流转仍需后端补齐。 |
| `examService` | 教师考试列表/详情、创建考试、学生考试列表、保存草稿、交卷 | 学生身份暂使用联调默认值 `student-001`。 |
| `gradingService` | 批改任务、教师复核、成绩汇总、成绩发布、学生成绩报告 | 单题级批改展示仍需后端返回更完整 item 字段。 |

### 14.4 前端质量门禁

每次调整真实接口适配后至少执行：

```powershell
pnpm web:typecheck
pnpm web:lint
pnpm web:build
```
