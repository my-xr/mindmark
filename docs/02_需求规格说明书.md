# 02 需求规格说明书

## 1. 文档目的

本文档定义 MindMark 当前 MVP 的功能需求、非功能需求、角色权限边界和验收标准。后续代码开发应以本文档为主要需求依据。

## 2. 需求优先级定义

| 优先级 | 含义 |
| --- | --- |
| P0 | MVP 闭环必须具备，缺失则无法完成考试闭环。 |
| P1 | MVP 体验增强，建议阶段 0 或阶段 1 实现。 |
| P2 | 后续版本扩展，不阻塞当前闭环。 |
| 暂缓 | 当前明确不做，除非需求变更。 |

## Iteration 15 前置确认补充：考试账号体系（P0 阻断项）

> 结论：当前系统仅具备开发态鉴权占位，不具备正式考试所需的学生/教师账号闭环。以下需求提升为考试闭环 P0，未完成前不得进入真实考试试运行。

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-ACCT-001 | 支持教师、TA、学生、管理员独立账号与角色绑定。 | P0 | 系统中可创建不同角色账号，登录后按角色进入对应工作台。 |
| FR-ACCT-002 | 支持导入学生名单并批量创建学生账号。 | P0 | 教师/TA/管理员可按班级导入学生名单，重复学号可识别并给出导入结果。 |
| FR-ACCT-003 | 学生初始密码默认为学号后 6 位。 | P0 | 导入创建账号后，学生可使用学号/账号 + 学号后 6 位完成首次登录；密码只保存哈希。 |
| FR-ACCT-004 | 学生首次登录必须修改密码。 | P0 | 首次登录返回必须改密标记，前端强制跳转改密页，改密完成前不得进入考试/答题页。 |

| FR-ACCT-006 | 账号、导入、改密和重置密码操作必须审计。 | P0 | 记录操作者、目标账号、操作类型、时间、结果与失败原因；不得记录明文密码。 |

## Iteration 15 补充需求：考试账号体系 P0

### 账号与登录
- 系统必须支持教师、助教、学生等角色账号登录。
- 学生首次登录或被重置密码后，系统必须强制跳转修改密码，修改完成前不得进入考试业务页面。
- 登录接口必须返回 `mustChangePassword`，供前端路由守卫判断。

### 学生名单导入
- 教师/助教必须能够下载学生名单导入模板。
- 教师/助教必须能够按班级导入学生名单并自动创建学生账号。
- 学生账号用户名为学号，初始密码为学号后 6 位。
- 已导入学生再次导入不得重复创建账号，应计入跳过数量。
- 学号不足 6 位、缺少学号或姓名的数据不得创建账号，应返回行级错误。

### 密码重置
- 教师/助教/管理员必须能够帮助学生重置密码。
- 重置后的密码规则为学号后 6 位，且学生下次登录必须修改密码。
- 系统不得在接口响应或日志中输出明文密码。

## Iteration 16 需求补充：生产级鉴权与账号治理硬化

- 鉴权技术选型从开发态占位 Token 正式切换为 Sa-Token；不得引入 Spring Security 作为本阶段鉴权实现。
- 登录成功后必须创建服务端会话并返回不包含用户 ID 的不透明 Bearer Token；`dev-token-*` 仅作为历史方案，不再签发、不再作为正式契约。
- 除 `/api/v1/auth/login` 与 `/api/v1/system/health` 外，`/api/v1/**` 业务接口默认要求已登录；未登录返回 `MM-401-001`，角色或班级范围不满足返回 `MM-403-001`。
- 账号治理新增密码策略：首次登录/主动改密的新密码至少 8 位，必须包含字母和数字，不能与旧密码、用户名或邮箱相同；学生初始密码仍为学号后 6 位并强制首次改密。
- 学生名单模板下载、学生名单导入、名单查询、密码重置均纳入鉴权拦截；教师/助教除角色满足外，还需要班级授权，管理员可管理全部班级。
## Iteration 17 需求补充：账号治理后台与安全审计可视化

- 管理员必须能够按关键词、角色、状态查询账号，统一查看账号角色、启停状态、强制改密、连续失败次数、临时锁定时间与最近登录时间。
- 管理员必须能够启用/禁用账号；禁用账号后后端应使该账号当前会话失效，避免禁用后继续访问。
- 管理员必须能够维护用户角色；为避免误锁定，系统禁止当前管理员移除自身 `ADMIN` 角色。
- 管理员必须能够解除临时锁定账号，清空连续登录失败次数与锁定截止时间。
- 管理员必须能够为教师/助教账号维护班级授权，授权角色限定为 `OWNER` 与 `ASSISTANT`，同一用户同一班级重复授权应更新而非重复创建。
- 管理员必须能够查询登录、登出、改密、账号治理、班级授权等审计日志，支持按操作人、目标用户、动作、结果筛选。
- 登录安全策略：账号连续 5 次密码错误后临时锁定 15 分钟；锁定期间登录返回无权访问并记录审计日志。

## 需求补充：题库课程筛选、AI 出题课程选择与五级难度（2026-07-19）

- 题库管理页必须支持按课程筛选题目；筛选参数为 `courseId`，`ALL` 表示全部课程。
- AI 出题审核页的“生成题目”模块中，课程必须来自当前用户可见课程下拉列表，不允许手动录入课程名称；提交时携带 `courseId`，并以课程名称作为生成上下文。
- 题目难度统一调整为 5 个等级：`VERY_EASY`（很简单）、`EASY`（简单）、`MEDIUM`（中等）、`HARD`（困难）、`VERY_HARD`（很困难）。

## 2026-07-19 需求补充：课程维度组卷边界

- 题目必须归属于一个课程；题目创建、导入、AI 生成审核入库均不得产生无课程归属题目。
- 试卷必须归属于一个课程；组卷时只能选择同课程题目，避免跨课程题目进入考试闭环。
- 难度等级统一为五级：很易、容易、中等、困难、很难。
## 2026-07-19 需求补充：考试防作弊与真实 AI 题库写入链路

### 学生答题安全（P0 浏览器侧约束）
- 学生进入考试答题页后必须展示距离考试结束的倒计时，倒计时归零时自动触发交卷。
- 学生开始答题前必须进入浏览器全屏；未处于全屏时不得编辑答案、保存草稿或提交答卷。
- 答题过程中系统必须检测切屏、窗口失焦、页面隐藏和退出全屏等异常行为，并在页面上明确提示异常次数。
- P0 规则：累计 3 次异常行为后前端自动提交当前答卷；后端仍以考试时间窗口与答卷状态机作为最终一致性边界。
- 当前防作弊为浏览器侧约束，后续应补齐异常行为后端上报、审计留痕、教师端查看与按考试配置阈值。

### 真实 AI 出题与题库写入（P0）
- AI 出题必须从“候选 Mock”升级为真实写入题库链路：生成后的题目保存为 `source=AI`、`status=PENDING_REVIEW`，等待教师审核。
- AI 出题必须携带 `courseId`，并根据课程表回填课程名称，不允许生成无课程归属题目。
- AI 出题链路使用 LangGraph 编排，基础节点为：输入校验 -> 课程解析 -> OpenAI/Anthropic Provider 生成 -> 中文内容校验 -> 题库持久化。
- 系统支持教师、助教、管理员选择 OpenAI 或 Anthropic 并配置自己的 API Key；调用时优先使用当前教师个人 Key，缺失时才使用对应 Provider 的全局环境变量配置。
- 教师个人 API Key 必须加密存储，接口只返回脱敏预览，不得在代码、文档、日志或响应中泄露明文 Key。
- 题库写入接口需覆盖手工创建、批量导入、AI 生成三条路径，并统一执行课程必填、五级难度、题型、分值、答案和解析校验。
