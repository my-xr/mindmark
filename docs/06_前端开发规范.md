# 06 前端开发规范

## 0. 项目边界说明

MindMark 根目录是完整项目根目录，不是前端项目根目录。前端业务代码必须放在 `apps/mindmark-web/` 下，禁止直接在项目根目录创建业务 `src/`。

更详细的工程划分见：

- `15_工程架构与系统划分.md`
- `16_前端系统框架设计.md`
- `17_代码规范与Lint规范.md`

## 1. 技术栈约束

- Vue 3
- TypeScript
- Vite
- 成熟 UI 库（具体选型以后续工程实际为准）
- 阶段 0 以 Mock 数据为主，但结构必须可平滑替换为真实 API。

## 2. 推荐目录结构

```text
src
├─ app/                 # 应用级配置、布局、路由守卫
├─ assets/              # 静态资源
├─ components/          # 通用组件
├─ composables/         # 组合式函数
├─ constants/           # 常量和枚举映射
├─ layouts/             # 页面布局
├─ mock/                # Mock 数据与模拟接口
├─ router/              # 路由配置
├─ services/            # API service 层
├─ stores/              # 状态管理
├─ styles/              # 全局样式
├─ types/               # 类型定义
├─ utils/               # 工具函数
└─ views/               # 页面级组件
```

## 3. 页面拆分规则

`views` 中页面文件建议每页不超过 400 行。超过时优先拆分为：业务组件、通用组件、composables、API service、类型定义、Mock 数据模块、常量和枚举。

## 4. 命名规范

| 类型       | 规则                | 示例                   |
| ---------- | ------------------- | ---------------------- |
| 页面组件   | PascalCase + View   | `QuestionBankView.vue` |
| 业务组件   | PascalCase          | `QuestionTypeTag.vue`  |
| composable | use + PascalCase    | `useExamTimer.ts`      |
| service    | camelCase + Service | `examService.ts`       |
| type 文件  | 领域名              | `exam.ts`              |
| mock 文件  | 领域名 + Mock       | `examMock.ts`          |
| 枚举       | PascalCase          | `ExamStatus`           |

## 5. TypeScript 规则

- 禁止滥用 `any`，确有必要时应说明原因。
- 接口返回类型必须显式定义。
- 核心枚举应统一放在 `types` 或 `constants`。
- 前端状态值必须与 `04_业务流程与状态机.md` 一致。
- Mock 数据必须符合类型定义。

## 6. UI 与交互规则

- 关键操作使用二次确认：发布考试、撤回考试、发布成绩、调整最终分数、删除草稿。
- 表格列表必须有空状态和加载状态。
- AI 结果必须有“接受 / 编辑 / 拒绝 / 重新生成”或等价操作。
- 考试答题页应减少干扰，不放置与考试无关入口。
- 成绩、批改、申诉页面要突出状态和可追溯信息。


## 6.1 表单组件使用规则

- 后续新增或重构页面时，禁止直接在业务页面中使用原生 `input`、`select`、`textarea`、`checkbox` 拼装表单。
- 若项目内已有封装组件，必须优先使用 `components/common` 下的表单组件，例如：
  - `AppFormControl`：用于普通输入框、数字输入框、密码框、搜索框、URL 输入框、下拉框、文本域。
  - `AppCheckbox`：用于单个布尔勾选项。
  - `AppChoiceChips`：用于多选标签/多选枚举。
- Ant Design Vue 的正式表单组件可以使用，但必须保持页面视觉、间距、字重、错误态与当前 MindMark 组件体系一致。
- 若现有组件不满足业务需求，应先扩展或新增通用组件，再在页面使用；禁止在页面内复制一套局部表单样式。
- 页面 CSS 只负责表单布局、栅格和区域间距；输入框、下拉框、文本域、复选项的 hover/focus/disabled 等控件级样式应内聚在组件内部。

## 7. Mock 开发规则

- Mock 数据不可随意写在页面中，应放入 `mock` 或 service 层。
- Mock 字段尽量贴近未来真实 API。
- Mock 应覆盖正常、空、异常、处理中等状态。
- 列表数据应包含不同状态，方便页面验收。

## 8. API service 规则

页面不得直接拼接 URL 或直接访问后端细节；所有数据访问通过 service 层；service 层返回统一类型，方便 Mock 和真实接口切换。

## 9. 开发前检查清单

- 页面是否在 `05_信息架构与页面清单.md` 中登记？
- 关联需求是否在 `02_需求规格说明书.md` 中存在？
- 状态是否符合 `04_业务流程与状态机.md`？
- 类型是否与 `07_领域模型与数据字典.md` 一致？
- 接口调用是否通过 service 层？
- 是否需要更新测试验收清单？

## 10. 样式模块分层规则

前端全局样式入口 `apps/mindmark-web/src/styles/index.css` 仅负责按顺序导入样式模块，不再直接堆积页面样式。新增或调整样式时遵循以下分层：

| 文件                           | 职责                                                                                    |
| ------------------------------ | --------------------------------------------------------------------------------------- |
| `tokens.css`                   | 设计变量、颜色、间距、阴影等 token。                                                    |
| `base.css`                     | 基础元素、全局 box-sizing、body、a、button 基础规则。                                   |
| `layout.css`                   | 门户布局、侧边栏、顶部栏、页面内容容器、PageHeader。                                    |
| `components.css`               | 通用按钮、卡片、表单、状态标签、题目预览等跨页面组件样式。                              |
| `teacher.css`                  | 教师端题库、AI 出题、组卷、考试创建、批改、成绩、复盘样式。                             |
| `admin.css`                    | 管理端学生名单、账号治理、班级授权、安全审计样式。                                      |
| `refinements.css`              | 页面精修层、局部体验增强和已有页面的轻量补丁。                                          |
| `modern.css`                   | 现代化视觉基调后置覆盖层，统一字体层级、卡片质感、简洁背景、按钮/标签密度。             |
| `density.css`                  | 字号收敛后的布局密度覆盖层，统一卡片间距、表格列宽和响应式降级。                        |
| `information-architecture.css` | 页面信息结构重排覆盖层，处理首屏模块数量、筛选首行折叠、列表/卡片对齐。                 |
| `themes.css`                   | 主题 token 与最终视觉覆盖层，维护 Light/Dark/Slate/Ocean/Forest 五套主题。              |
| `visual-alignment.css`         | 页面级真实视觉验收后的最终对齐覆盖层，统一 PageHeader、区块标题、筛选、列表行和操作区。 |

约束：

- 新增页面私有样式优先写入对应业务模块；只有可复用组件样式才进入 `components.css`。
- `refinements.css` 只能放置局部精修补丁，不应承载新业务页面主体样式。
- `modern.css` 负责现代视觉基调，`density.css` 负责字号缩小后的布局密度；`information-architecture.css`、`themes.css` 与 `visual-alignment.css` 必须后置导入，用于页面结构重排、主题最终覆盖和真实视觉对齐，避免在同一 CSS 文件内重复 selector 触发 Stylelint `no-duplicate-selectors`。
- 视觉精修默认遵循“少加粗、低密度、轻阴影、清晰层级”原则：页面标题通常不超过 19px/650，按钮和标签尽量保持 12px 左右字号与 560 以下字重。
- 圆角默认保持克制：常规按钮/菜单项约 6px，内容块 8px，大卡片 12px；除用户头像、状态胶囊等必要场景外，避免滥用超大圆角。
- 左侧导航可使用统一 emoji 标签增强识别度；不再使用无语义圆点作为菜单主标记。折叠态应保留 emoji 与 `title` 提示，保证可识别性。
- 样式新增后必须通过 `pnpm web:quality` 中的 Stylelint 检查。

## 11. 2026-07-18 简洁视觉与表格/筛选补充规则

- 默认视觉方向调整为“现代简洁、白底轻边框、低阴影”，不再使用会遮挡文字或增加噪音的全屏网格、强光晕、玻璃拟态背景。
- 全局圆角继续收敛 2px：`--mm-radius-md` 为 `8px`，`--mm-radius-lg` 为 `12px`；新增组件应优先使用 token，避免重新引入大圆角。
- 页面筛选项超过 3 个，或筛选区/创建配置区明显挤占首屏时，必须提供“展开/收起”能力；默认是否收起按使用频率决定，查询筛选可默认收起，核心创建表单可默认展开或提供显著展开入口。
- 表格/类表格列表不得通过 `overflow: hidden` 掩盖数据溢出；必须为容器提供横向滚动、合理最小列宽和单元格 `min-width: 0`，长文本使用省略或换行策略。
- 筛选区、表格和卡片的视觉层级应优先靠间距、浅边框、字体层级表达，减少粗体和高饱和装饰。

## 12. 2026-07-18 字号进一步收敛规则

- 全局基础字号调整为 `13px`，页面正文、表格、表单和导航优先继承该基础字号。
- 页面主标题建议控制在 `19px` 左右，区块标题控制在 `15px` 左右，卡片指标数字控制在 `20px` 左右。
- 按钮、筛选项、辅助说明、表头、导航项建议使用 `12px` 左右；状态标签可保持 `11px`。
- 不再通过增加粗体弥补字号缩小，优先用颜色、间距和浅边框表达层级。

## 13. 2026-07-18 字号缩小后的布局密度规则

- 字号缩小后必须同步检查卡片宽度、表格列宽、列表左右留白和 sticky 侧栏宽度，避免出现“字变小但容器仍过宽”的失衡。
- 教师工作台类总览页应避免所有卡片单列满屏堆叠；可将轻量待办与辅助信息组成二级栅格，让待办列表保持合适阅读宽度。
- `density.css` 是布局密度覆盖层，导入顺序必须在 `modern.css` 之后；新增密度规则应优先使用更具体 selector，避免与同文件 selector 重复。
- 表格最小宽度应根据实际字号和列内容重新评估，优先减少固定宽列，再保留必要的横向滚动兜底。
- 主要双栏/三栏页面在 `1280px` 以下必须降级为单列，sticky 侧栏同步取消，避免内容区被过度挤压。

## 12. 2026-07-19 页面信息结构重排与主题规则

- 顶部导航栏提供 5 套主题：Light、Dark、Slate、Ocean、Forest；默认主题必须为 Light，Light 下左侧导航使用白/灰基调，不再默认使用深蓝侧栏。
- 主题状态由 `useAppStore` 管理，持久化到 `localStorage`，通过 `document.documentElement.dataset.theme` 驱动 CSS token 覆盖；新增主题只能扩展 token，不得在页面组件中硬编码整套颜色。
- 教师工作台只保留指标、近期待办和快捷入口等高频业务信息；后端接口契约、技术说明、低频提示不得占用主工作区。
- 筛选区默认可见，但多行筛选默认仅展示第一行；通过“展开全部 / 收起到一行”控制完整条件，避免继续缩小字号来解决拥挤问题。
- 表格和状态标签必须优先保证文字可读：标签不得覆盖题干、知识点等主文本；长文本使用换行、省略或横向滚动兜底。
- 试卷列表、考试列表优先使用轻量行列表风格，减少强卡片、强阴影和悬浮位移，主操作位置保持在区块右上或行尾。

## 13. 2026-07-19 页面级真实视觉验收规则

- PageHeader、卡片、表格和双/三栏工作区必须共享同一内容起线；禁止使用装饰性左竖线造成标题与卡片错位。
- 区块标题统一使用“左侧标题/说明 + 右侧操作”的两列结构；窄屏时降级为上下排列，操作区左对齐。
- 列表行、表头和操作列必须使用一致的左右内边距；题库、考试、成绩、账号等类表格行的操作入口默认右对齐。
- 卡片 hover 只允许轻微边框/阴影变化，不使用上浮位移，避免同屏多个模块产生漂移感。
- 视觉验收发现的跨页面对齐问题优先写入 `visual-alignment.css`；确认稳定后再回迁到基础模块，避免分散补丁。

## 13. 2026-07-19 页面级真实视觉验收补充规则

- 多列 Grid 容器内的卡片不得继承通用 `.content-card + .content-card` 纵向间距；如 `.dashboard-main-grid`、`.overview-grid`、`.paper-builder-layout`、`.grading-layout` 等，必须在最终覆盖层中重置 `margin-top: 0`，避免同一行卡片出现 14px 下沉。
- 题库、考试、成绩、账号等类表格必须先保证容器无横向溢出，再讨论视觉密度；表格行应显式设置 `box-sizing: border-box`、`min-width: 0`，固定列宽只保留必要操作列。
- 选中态不再使用可能遮挡文字的内嵌蓝色条或强阴影；统一改为轻背景 + 边框强调，避免“蓝色格子遮挡文字”。
- 局部组件统一优先通过最终覆盖层收敛已上线页面差异，稳定后再回迁到 `components.css`、`teacher.css` 或 `admin.css`。

## 14. 2026-07-20 前端操作按钮与布局统一规范

本轮完成前端操作按钮组件化收敛，后续页面开发与重构必须遵循以下约束：

- 页面级主操作、次操作、危险操作统一使用 `components/common/AppActionButton.vue`，禁止继续新增散落的 `primary-button` / `secondary-button` / `danger-button` 业务按钮实现。
- `AppActionButton` 统一承载 `primary`、`secondary`、`danger`、`tag`、`tag-danger` 五类语义；新增、保存、提交等强主操作使用 `primary`，删除、禁用、移除等破坏性操作使用 `danger` 或 `tag-danger`。
- 顶部操作区使用 `page-header-actions`，模块操作区使用 `section-actions` 或 `page-section-title__actions`，行内操作使用 `inline-actions`；按钮间距由全局样式控制，不在页面内临时写 gap。
- 列表、表格、卡片之间默认以 20px 为页面节奏；筛选卡片、内容卡片、详情抽屉的主次操作位置必须保持一致。
- 链接型操作同样使用 `AppActionButton` 的 `to` 属性实现，避免同一页面混用 RouterLink 按钮样式与原生 button 样式。
- 需要图标标签化的高频操作优先使用 `icon` / `iconOnly` / `size="sm"`，文字仅用于解释动作，不再为单页单独创建重复按钮样式。
- 每次按钮或布局规范调整后，必须执行 `pnpm --filter mindmark-web lint`、`stylelint`、`typecheck` 验收。

## 15. 2026-07-20 页面级布局一致性二次巡检规范

- 教师端、学生端、管理端主要业务页面根容器统一使用 `page-shell + 页面专属 class`，页面级纵向节奏由 `page-shell` 的 `gap: 20px` 统一控制。
- `PageHeader`、筛选卡片、内容卡片、指标栅格、管理端概览栅格等作为 `page-shell` 直接子元素时，不再叠加 `margin-top` / `margin-bottom`，避免出现“grid gap + 外边距”导致的间距不一致。
- 多栏工作区（如教师工作台、试卷组卷、批改中心、成绩中心、学生成绩反馈、复盘分析）统一使用 20px 横向间距；内部表单、列表、按钮组只保留组件自身的紧凑间距。
- 页面操作区统一使用 `page-header-actions`、`section-actions`、`inline-actions`、`page-section-title__actions`，按钮间距统一为 `gap: 8px 10px`，禁止在单页继续写临时操作区间距。
- 若局部页面使用 scoped 样式定义了根容器或直接子模块 margin，必须在最终视觉覆盖层中显式收敛，或回迁到组件/页面基础样式中，确保同屏模块起线、卡片间距和操作区节奏一致。
