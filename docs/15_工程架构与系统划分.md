# 15 工程架构与系统划分

## 1. 关键结论

MindMark 当前目录是**完整项目根目录**，不是单一前端项目目录，也不是单一后端项目目录。

因此后续开发必须在当前项目内创建独立的前端、后端和可选辅助服务子项目，不能直接在项目根目录创建 `src/` 写业务代码。

## 2. 推荐根目录结构

```text
MindMark/
├─ docs/                         # 项目文档中心
├─ apps/                         # 可运行应用
│  ├─ mindmark-web/              # Phase 0/1 前端主项目：Web 端统一入口
│  ├─ mindmark-server/           # Phase 2 后端主项目：Spring Boot 模块化单体
│  └─ mindmark-ai-service/       # Phase 3 可选：FastAPI AI/RAG 辅助服务
├─ packages/                     # 跨应用共享包，按需创建
│  ├─ shared-types/              # 前后端共享类型或 OpenAPI 生成产物，后续可选
│  └─ eslint-config/             # 统一 lint 配置，后续可选
├─ infra/                        # Docker、数据库、Redis、部署脚本，后续创建
├─ scripts/                      # 项目级脚本，后续创建
├─ package.json                  # monorepo 工作区入口，创建前端时再生成
├─ pnpm-workspace.yaml           # pnpm workspace 配置，创建前端时再生成
└─ README.md                     # 项目根说明，后续创建
```

## 3. 第一阶段系统边界

第一阶段目标是考试系统闭环，开发顺序为：

```text
先前端 Mock 闭环 → 再后端真实接口 → 再 AI 能力真实接入
```

当前阶段只需要优先创建：

```text
apps/mindmark-web/
```

后端项目 `apps/mindmark-server/` 在前端核心原型稳定后再创建。

## 4. 前端系统划分

### 4.1 Phase 0/1 采用一个 Web 前端主项目

| 系统 | 项目目录 | 当前是否开发 | 说明 |
| --- | --- | --- | --- |
| Web 统一端 | `apps/mindmark-web` | 是 | Vue 3 + TypeScript。承载教师端、学生端、管理员端三类门户。 |
| 移动 H5 | 暂不单独建项目 | 否 | 学生答题页先在 Web 项目内做响应式预留，后续再评估是否独立。 |
| 原生移动 App | 暂不建设 | 否 | 当前 MVP 不做 iOS / Android 原生应用。 |

### 4.2 为什么先做一个 Web 项目

1. 当前 MVP 以院校 / 教师内部考试闭环为主，桌面 Web 是教师高频场景。
2. 学生考试端也可以先通过浏览器访问，避免过早拆分多端导致成本上升。
3. 教师端、学生端、管理端共享大量类型、状态、Mock、API service 和设计系统。
4. 统一 Web 项目更适合 Phase 0 快速打通完整闭环。

### 4.3 Web 内部按门户隔离

虽然采用一个 Web 项目，但内部必须按门户隔离：

```text
/teacher/*   教师 / TA 工作台，属于后台业务
/student/*   学生考试与成绩反馈，属于前台业务
/admin/*     管理员控制台，属于后台管理
```

对应布局：

| 门户 | 路由前缀 | 布局 | 主要角色 |
| --- | --- | --- | --- |
| 教师后台 | `/teacher` | `TeacherLayout` | 教师、TA |
| 学生前台 | `/student` | `StudentLayout` | 学生 |
| 管理后台 | `/admin` | `AdminLayout` | 管理员 |
| 登录与错误页 | `/auth`、`/error` | `BlankLayout` | 全部 |

## 5. 前台 / 后台划分

| 类型 | 范围 | 说明 |
| --- | --- | --- |
| 前台 | 学生考试中心、考试须知、在线答题、成绩反馈、申诉 | 面向学生，强调稳定、低干扰、清晰反馈。 |
| 后台 | 教师工作台、题库、AI 出题、组卷、考试管理、批改、成绩、复盘、管理员配置 | 面向教师、TA、管理员，强调效率、可审核、可追溯。 |

Phase 0/1 中，前台和后台在同一个 `mindmark-web` 项目中实现，通过路由、布局、权限和菜单隔离。

## 6. 后端系统划分

| 系统 | 项目目录 | 当前是否开发 | 技术栈 | 说明 |
| --- | --- | --- | --- | --- |
| 后端主服务 | `apps/mindmark-server` | 暂缓 | Spring Boot | Phase 2 创建，采用模块化单体。 |
| AI 辅助服务 | `apps/mindmark-ai-service` | 暂缓 / 可选 | Python FastAPI | RAG、文档解析、复杂智能体能力需要时再创建。 |

后端主服务初步模块：

```text
auth / rbac / audit / course / question-bank / paper / exam / answer / grading / score / review / notification / ai-provider
```

## 7. Monorepo 管理建议

- 包管理器：优先使用 `pnpm`。
- 工作区：使用 `pnpm-workspace.yaml` 管理 `apps/*` 和 `packages/*`。
- 根目录只放项目级配置、文档、脚本和工作区配置。
- 应用级依赖放在各自子项目中。
- 根目录禁止出现业务级 `src/`。

## 8. 开发顺序

| 顺序 | 事项 | 产物 |
| --- | --- | --- |
| 1 | 创建 monorepo 基础配置 | 根 `package.json`、`pnpm-workspace.yaml` |
| 2 | 创建前端主项目 | `apps/mindmark-web` |
| 3 | 建立前端架构、路由、布局、Mock | 教师/学生/管理端基础框架 |
| 4 | 打通考试闭环前端原型 | 题库、AI 出题、组卷、答题、批改、成绩、复盘 |
| 5 | 创建后端主项目 | `apps/mindmark-server` |
| 6 | 替换 Mock 为真实接口 | Spring Boot + PostgreSQL + Redis |
| 7 | 接入真实 AI Provider | API Key、安全、审计、人审流 |

## 9. 开发前硬性约束

- 不得直接在项目根目录创建业务 `src/`。
- 不得把教师端、学生端、管理端拆成三个独立前端项目，除非后续需求变更明确要求。
- 不得在 Phase 0 直接创建复杂后端或数据库实现，除非前端原型已经稳定。
- 不得在代码中硬编码真实 API Key。
- 每次新增系统、目录或项目边界变化，必须更新本文档和 `12_需求变更与决策记录.md`。

## 10. Iteration 6 后端接口契约准备结论

Iteration 6 仅做后端接口契约准备，不创建 `apps/mindmark-server`，不引入数据库和后端运行时。当前阶段新增 `19_后端接口契约准备.md`，用于记录前端 Mock service 到后端接口的映射、后端模块边界和 Phase 2 启动检查清单。

后续真正进入后端开发时，应按以下顺序推进：

1. 创建 `apps/mindmark-server` 子项目。
2. 建立 auth / rbac / audit 基础能力。
3. 优先实现 P0 考试闭环接口。
4. 将 `apps/mindmark-web/src/services/*` 逐步从 Mock 替换为 HTTP 实现。
5. 再接入 P1 AI 与复盘接口。


## 12. Iteration 7 后端主项目创建更新

Iteration 7 起，`apps/mindmark-server` 已创建为后端主项目骨架，当前状态从“暂缓创建”更新为“已创建骨架，业务接口待实现”。

当前已落地产物：

- Spring Boot + Maven 后端子项目；
- `common/api` 统一响应、错误码、分页响应模型；
- `common/exception` 全局异常处理；
- `system` 健康检查接口；
- `modules/*` 后端模块包结构；
- PostgreSQL / Redis / OpenAI / Anthropic Provider 的环境变量配置入口；
- Flyway 基线迁移；
- 静态 OpenAPI 契约文件 `apps/mindmark-server/openapi/mindmark-api.yaml`。

约束保持不变：根目录仍禁止创建业务 `src/`；前端在 `apps/mindmark-web`，后端在 `apps/mindmark-server`，AI 辅助服务如需创建仍放在 `apps/mindmark-ai-service`。
