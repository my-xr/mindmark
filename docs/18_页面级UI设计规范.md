# 18 页面级 UI 设计规范

## 1. 目标

本文档定义 MindMark Phase 0/1 前端页面级 UI 规范，用于保证教师后台、学生前台、管理后台在视觉、交互、状态反馈和组件使用上的一致性。后续页面开发必须先遵循本文档，再进入实现。

## 2. 设计原则

| 原则         | 说明                                                 |
| ------------ | ---------------------------------------------------- |
| 企业级清晰   | 信息层级明确，避免炫技式视觉干扰业务判断。           |
| 考试场景稳定 | 学生答题页低干扰、高可读、强状态反馈。               |
| AI 可解释    | AI 结果必须展示来源、置信度、风险和人工审核入口。    |
| 状态可见     | 考试、批改、成绩、申诉等流程状态必须被清楚表达。     |
| 可扩展       | 先建立统一 token、组件和布局约束，便于后续多端扩展。 |

## 3. 视觉基调

| 门户     | 基调                     | 设计重点                                 |
| -------- | ------------------------ | ---------------------------------------- |
| 教师后台 | 专业、效率、数据密度适中 | 快速定位任务、批量操作、数据分析。       |
| 学生前台 | 稳定、专注、低干扰       | 答题沉浸感、倒计时、保存状态、提交确认。 |
| 管理后台 | 简洁、克制、可审计       | 权限配置、用户管理、日志查看。           |

## 4. 色彩规范

| Token                       | 建议值    | 用途                         |
| --------------------------- | --------- | ---------------------------- |

| `--mm-color-primary-hover`  | `#1d4ed8` | 主色 hover。                 |
| `--mm-color-success`        | `#16a34a` | 成功、已完成、通过。         |
| `--mm-color-warning`        | `#f59e0b` | 待处理、低置信度、风险提示。 |
| `--mm-color-danger`         | `#dc2626` | 错误、拒绝、异常、危险操作。 |
| `--mm-color-info`           | `#0891b2` | 信息提示、AI 辅助。          |
| `--mm-color-text`           | `#111827` | 主文本。                     |
| `--mm-color-text-secondary` | `#4b5563` | 次级文本。                   |
| `--mm-color-text-tertiary`  | `#9ca3af` | 辅助文本。                   |
| `--mm-color-border`         | `#e5e7eb` | 边框。                       |

状态颜色必须通过统一 `StatusTag` 或状态映射使用，不允许页面随意硬编码。危险操作必须二次确认。AI 低置信度必须使用 warning 或 danger，并配合文字说明。

## 5. 字体、字号、间距

| 层级        | 字号 | 行高 | 用途                       |
| ----------- | ---- | ---- | -------------------------- |
| 页面标题    | 24px | 32px | 页面主标题。               |
| 区块标题    | 18px | 26px | 卡片、表单、分析模块标题。 |
| 表格 / 正文 | 14px | 22px | 常规内容。                 |
| 辅助说明    | 13px | 20px | 表单提示、状态说明。       |
| 极弱说明    | 12px | 18px | 时间、ID、审计摘要。       |

| Token           | 值   | 用途                   |
| --------------- | ---- | ---------------------- |
| `--mm-space-xs` | 4px  | 紧密元素间距。         |
| `--mm-space-sm` | 8px  | 标签、按钮内部间距。   |
| `--mm-space-md` | 16px | 表单项、卡片内部间距。 |
| `--mm-space-lg` | 24px | 区块间距。             |
| `--mm-space-xl` | 32px | 页面大区块间距。       |

要求：中文界面默认系统字体；学生答题正文不小于 15px；编程题代码区域使用等宽字体。

## 6. 布局规范

### 6.1 教师后台布局

```text
顶部栏：系统名、全局搜索（后续）、消息、用户
侧边栏：教师端主导航
内容区：PageHeader + 筛选/操作区 + 主内容卡片
```

- 左侧菜单可折叠。
- 页面主操作放在 `PageHeader` 右侧。
- 列表页筛选区在表格上方，使用卡片承载。
- 数据看板优先使用卡片网格。

### 6.2 学生前台布局

```text
普通页：顶部简洁导航 + 内容区
答题页：专注考试栏 + 题目区 + 题卡区 + 底部/侧边提交操作
```

- 答题页不展示无关导航。
- 答题页进入“考试专注模式”，隐藏学生普通导航，只保留考试标题和考试控制。
- 倒计时固定在答题页顶部右侧，仅展示时间数字；保存状态、剩余题数必须始终可见。
- 课程名、试卷名、满分等辅助信息不应与题目区争夺首屏空间。
- 未进入全屏时必须明确提示“请先进入全屏后开始作答”，答题控件保持禁用。
- 提交按钮必须二次确认。
- 自动保存失败必须明显提示。
- 监考细节默认折叠，仅在学生主动展开时展示异常记录和处理说明。
- 答题卡展开后题号区域允许内部滚动，但交卷按钮必须固定在卡片底部可见区域。
- 顶部左侧提供独立的紧凑返回按钮，不挤压考试标题；考试进行中点击必须二次确认，且不得自动交卷。
- 未进入全屏时，试题区和答题卡必须使用遮罩锁定，不仅依赖禁用控件或顶部文字提示；遮罩中心应提供进入全屏的主操作。
- 遮罩仅覆盖答题工作区，不覆盖顶部状态栏，保证学生始终能看到并操作全屏入口。

### 6.3 管理后台布局

- 与教师后台共享后台基础布局。
- 导航与权限更偏系统配置和审计。
- 高风险配置修改必须二次确认。

## 7. 页面类型规范

### 7.1 工作台页面

必须包含关键指标卡片、待办任务列表、快捷入口、最近考试 / 最近批改 / 最近通知。

### 7.2 列表页面

必须包含 `PageHeader`、筛选区、主操作按钮、表格、分页、空状态、加载状态、错误状态。每行操作不超过 4 个，超过进入“更多”；危险操作二次确认。

### 7.3 表单页面

必须包含表单分区、必填校验、保存 / 取消、离开未保存提示、提交失败错误摘要。

### 7.4 审核页面

适用于 AI 题目审核、AI 批改复核。必须包含原始内容、AI 输出、置信度 / 风险标签、人工操作、操作审计摘要。

### 7.5 分析页面

必须包含指标卡片、图表、明细表、解释说明、导出 / 生成讲评稿入口（后续）。

## 8. 核心组件 UI 规范

| 组件                | UI 要求                                         |
| ------------------- | ----------------------------------------------- |
| `PageHeader`        | 左侧标题和说明，右侧主操作；支持面包屑。        |
| `StatusTag`         | 使用统一状态颜色和文案，不允许页面自定义散落。  |
| `QuestionTypeTag`   | 六类题型统一颜色和简称。                        |
| `DifficultyTag`     | 简单/中等/困难分别使用 success/warning/danger。 |
| `AiConfidenceTag`   | 高/中/低置信度明确分级。                        |
| `ExamTimer`         | 剩余 10 分钟 warning，剩余 3 分钟 danger。      |
| `QuestionNavigator` | 区分未答、已答、标记、当前题。                  |
| `EmptyState`        | 包含图标、标题、说明、可选操作。                |
| `ErrorState`        | 包含错误说明、重试操作、traceId（后端阶段）。   |

## 9. 状态、空状态与错误文案

- 状态文案使用中文，代码状态使用英文枚举。
- 文案应解释“现在是什么状态”和“下一步能做什么”。
- 例如：`批改完成待发布` 比 `已批改` 更适合成绩中心。

| 场景         | 文案建议                                   | 操作建议           |
| ------------ | ------------------------------------------ | ------------------ |
| 题库为空     | 暂无题目，先创建一道题或使用 AI 生成题目。 | 新建题目 / AI 出题 |
| 考试为空     | 暂无考试，创建考试后可发布给学生。         | 创建考试           |
| 批改任务为空 | 当前没有待批改任务。                       | 返回考试列表       |
| 学生无考试   | 当前没有待参加考试，请关注老师通知。       | 刷新               |

## 10. 关键操作确认规范

必须二次确认：发布考试、撤回考试、删除草稿、提交试卷、接受 AI 批改并作为最终成绩、调整最终分数、发布成绩、驳回申诉、修改权限。确认弹窗必须说明影响范围和是否可撤销。

## 11. 响应式与无障碍

| 宽度           | 策略                                    |
| -------------- | --------------------------------------- |
| ≥ 1200px       | 标准桌面布局，题卡右侧固定。            |
| 768px - 1199px | 题卡可折叠或置于顶部。                  |
| < 768px        | 仅做基础可用，不作为 Phase 0 重点验收。 |

- 关键按钮必须有明确文字，不只使用图标。
- 表单错误必须靠近字段展示。
- 颜色不能作为唯一状态表达方式，必须有文字或图标辅助。
- 答题页操作区必须键盘可聚焦。

## 12. 页面级结构约定

### 12.1 后台列表页骨架

适用：题库、试卷、考试、批改任务、成绩、用户管理。

```text
PageHeader
└─ 标题 / 说明 / 主操作
FilterCard
└─ 关键词、状态、类型、时间范围、高级筛选
Toolbar
└─ 批量操作、刷新、导出（后续）、列设置（后续）
DataTable
└─ 状态列、关键字段列、更新时间列、行操作
Pagination
EmptyState / ErrorState / Loading
```

约束：筛选项默认一行展示，超过 4 项可折叠；表格第一列优先为业务主名称，最后一列固定为操作列；列表页必须提供 loading、empty、error 三类状态占位。

### 12.2 后台详情 / 审核页骨架

```text
PageHeader
└─ 返回、标题、状态、主操作
SummaryCard
└─ 核心信息、流程状态、风险提示
MainContent
├─ 左侧：业务内容 / 表单 / 题目 / 答卷
└─ 右侧：审核操作 / 状态流 / 审计记录 / 辅助说明
FooterActions（必要时）
```

AI 相关详情必须显示来源、模型/规则版本（Mock 阶段可占位）、置信度、风险提示、人工审核结论。

### 12.3 学生考试页骨架

```text
ExamHeader
└─ 考试名称、时间、倒计时、保存状态
QuestionArea
└─ 题干、附件/材料、作答控件、上一题/下一题
QuestionNavigator
└─ 题号、已答、未答、标记、当前题
SubmitArea
└─ 剩余未答提示、提交按钮、二次确认
```

提交确认必须展示已答题数、未答题数、提交后是否可修改。网络异常、保存失败、考试结束必须强提示。

答题页首屏验收约束：

1. 顶部左侧只保留考试标题，不重复展示“在线考试”、课程、试卷和满分信息。
2. 顶部右侧按“进入全屏、保存状态、监考入口、时间数字”排列，不额外展示“剩余时间”标签，时间数字位于最右侧。
3. 答题进度只展示“已答 / 总题数”和“剩余题数”，快捷键等低频说明不占用首屏。
4. 题目区和按题型分组的答题卡是首屏主内容，二者应在首屏同时可见。
5. 退出全屏、切屏、窗口失焦等事件必须记录；达到异常阈值时自动交卷或阻断继续作答。

## 13. Phase 1 页面 UI 蓝图

### 13.1 教师工作台 `/teacher/dashboard`

| 区域     | 内容                                       | UI 要求                              |
| -------- | ------------------------------------------ | ------------------------------------ |
| 顶部概览 | 今日考试、待批改、待审核 AI 题目、异常提醒 | 4 个指标卡，使用统一图标与趋势文案。 |
| 待办任务 | 待发布考试、待批改试卷、待复核 AI 结果     | 列表按紧急程度排序，状态标签右对齐。 |
| 快捷入口 | AI 出题、创建试卷、发布考试、进入批改      | 使用卡片按钮，不超过 6 个。          |
| 最近动态 | 最近考试、最近成绩发布、系统通知           | 使用时间线或简表，弱化次要信息。     |

### 13.2 题库管理 `/teacher/questions`

| 区域   | 内容                                               | UI 要求                                      |
| ------ | -------------------------------------------------- | -------------------------------------------- |
| 筛选区 | 关键词、题型、难度、知识点、来源、状态             | 默认展示常用筛选，知识点后续可替换为树选择。 |
| 操作区 | 新建题目、AI 生成题目、导入题目（后续）、批量审核  | 主按钮为“新建题目”，AI 入口为次主按钮。      |
| 表格   | 题干摘要、题型、难度、知识点、来源、状态、更新时间 | 题干摘要最多两行，超出省略。                 |
| 行操作 | 预览、编辑、加入试卷、停用/启用                    | 危险操作二次确认。                           |

状态：草稿、待审核、已入库、已停用。

### 13.3 AI 出题审核 `/teacher/ai-questions`

| 区域     | 内容                                         | UI 要求                                        |
| -------- | -------------------------------------------- | ---------------------------------------------- |
| 生成表单 | 学科、知识点、题型、难度、数量、补充要求     | 分组表单，生成按钮固定在表单底部。             |
| 生成结果 | AI 题目卡片列表                              | 每张卡展示题干、答案、解析、置信度、风险标签。 |
| 审核操作 | 接受、编辑后接受、拒绝、重新生成             | 操作按钮固定顺序，接受前必须可预览题目结构。   |
| 风险提示 | 低置信度、疑似歧义、答案不唯一、知识点不匹配 | 使用 warning/danger 标签，不允许只显示百分比。 |

AI 生成内容进入正式题库前必须经过人工确认。

### 13.4 试卷管理 `/teacher/papers`

| 区域   | 内容                                         | UI 要求                          |
| ------ | -------------------------------------------- | -------------------------------- |
| 筛选区 | 关键词、状态、创建人、更新时间               | 与其他后台列表页保持一致。       |
| 操作区 | 新建试卷、从题库组卷、AI 辅助组卷（后续）    | Phase 1 优先 Mock 手动组卷入口。 |
| 表格   | 试卷名称、题量、总分、状态、创建人、更新时间 | 总分和题量使用数字强调。         |
| 预览区 | 题目结构、分值分布、题型分布                 | 可在详情页或抽屉中展示。         |

状态：草稿、已组卷、已归档。

### 13.5 考试管理 `/teacher/exams`

| 区域     | 内容                                                | UI 要求                              |
| -------- | --------------------------------------------------- | ------------------------------------ |
| 筛选区   | 关键词、考试状态、班级、时间范围                    | 时间范围为核心筛选项。               |
| 操作区   | 创建考试、发布考试、复制考试                        | 发布考试必须二次确认。               |
| 表格     | 考试名称、试卷、班级、开始/结束时间、状态、参加人数 | 状态列必须突出“进行中/异常/已结束”。 |
| 监控入口 | 进入考试监控、查看提交情况                          | 进行中考试操作优先级高。             |

状态：草稿、待开始、进行中、已结束、已撤回。

### 13.6 批改中心 `/teacher/grading`

| 区域     | 内容                                       | UI 要求                           |
| -------- | ------------------------------------------ | --------------------------------- |
| 任务筛选 | 考试、题型、批改状态、是否 AI 已批改       | 支持快速筛选“只看待人工复核”。    |
| 任务列表 | 学生、题目、AI 分数、人工分数、状态        | AI 分与人工分并列展示，避免误读。 |
| 批改面板 | 题干、学生答案、参考答案、评分点、评分输入 | 评分输入必须靠近答案区。          |
| AI 建议  | 建议分、理由、置信度、风险                 | 接受 AI 分数必须可审计。          |

状态：待批改、AI 已批、待复核、已完成、存在争议。

### 13.7 成绩中心 `/teacher/scores`

| 区域   | 内容                                   | UI 要求                      |
| ------ | -------------------------------------- | ---------------------------- |
| 指标区 | 平均分、最高分、最低分、及格率、提交率 | 使用指标卡，重要指标带解释。 |
| 分布图 | 分数段分布、题型得分、知识点薄弱项     | 图表下方必须有文字解释。     |
| 明细表 | 学生、分数、排名、状态、是否发布       | 发布前展示“待发布”状态。     |
| 操作区 | 发布成绩、导出、生成讲评稿（后续）     | 发布成绩必须二次确认。       |

### 13.8 复盘分析 `/teacher/reviews`

| 区域     | 内容                               | UI 要求                          |
| -------- | ---------------------------------- | -------------------------------- |
| 考试选择 | 选择已结束考试                     | 默认展示最近一次已结束考试。     |
| 班级分析 | 分数分布、薄弱知识点、异常题目     | 分析结论必须可读，不只展示图表。 |
| 学生分析 | 学生薄弱项、建议练习方向           | Phase 1 可先做 Mock 列表。       |
| AI 讲评  | 讲评稿草稿、风险提示、人工编辑入口 | AI 内容不得直接发布。            |

### 13.9 学生考试列表 `/student/exams`

| 区域     | 内容                                 | UI 要求                              |
| -------- | ------------------------------------ | ------------------------------------ |
| 考试卡片 | 考试名称、时间、状态、剩余时间、入口 | 使用卡片列表，进行中考试突出主操作。 |
| 状态筛选 | 全部、待开始、进行中、已结束         | 状态筛选不超过 4 项。                |
| 提醒区   | 考试纪律、设备建议、网络提醒         | 使用轻量提示，不制造焦虑。           |

### 13.10 考试须知 `/student/exams/:id/notice`

| 区域     | 内容                               | UI 要求                  |
| -------- | ---------------------------------- | ------------------------ |
| 考试信息 | 名称、时间、题量、总分、限时       | 信息卡清晰展示。         |

### 公共组件边界

- `PageSection`：用于承载页面内稳定的内容模块，统一 `content-card`、标题、描述、右侧操作区与分割线结构。页面不再重复手写 `section-title` 骨架。
- `SummaryStrip`：用于当前对象摘要、班级摘要、复盘摘要等“标题 + 说明 + 轻量指标”的横向信息条，避免各页面重复维护摘要布局。
- 本轮只收敛复盘分析与学生名单页面中的高重复模块，不改变题库、组卷、考试管理等页面既有交互，避免小范围优化扩大成全局重构。

### 使用要求

- 页面级组件优先负责数据编排和业务动作，标题区、操作区、摘要区交给公共组件承载。
- `PageSection` 的 `actions` 插槽只放主次按钮、状态标签、计数标签，不放复杂业务表单。
- `SummaryStrip` 的指标数量建议 1-3 个；超过 3 个应使用独立指标栅格，避免摘要条过载。
- 视觉保持现代简洁：轻边框、低阴影、低干扰背景；不得恢复强发光或遮挡文字的科技感效果。

## 2026-09-18 学生答题页顶部状态区补充

- 考试专注模式顶部右侧的保存状态和倒计时使用统一尺寸：150px × 40px；状态文字和时间数字垂直居中。
- 考试状态栏使用全视口宽度，桌面端固定高度 56px，与系统顶部导航栏保持一致；试题与答题卡区域不跟随状态栏无限拉宽。
- 顶部状态文案遵循信息减法原则：不重复展示“在线考试”和“剩余时间”，使用按钮、状态卡和时间数字表达当前状态。
- 交卷后顶部只显示“已交卷”状态卡，隐藏倒计时、全屏操作和监考入口，避免产生“仍可作答”的误导。
- 状态卡使用轻边框、低饱和背景和单一状态色，不使用大面积高亮或装饰性发光。
- 移动端状态卡改为满宽等高布局，禁止因文字长度导致同一行控件高低不齐。
- 考试须知页桌面端内容宽度上限为 1180px；“考试入口”和“必须全屏作答”并排且等高，窄屏自动单列。

## 2026-09-18 认证与错误反馈补充

- 退出登录属于破坏当前会话的操作，必须使用确认弹窗；确认按钮使用危险色，默认焦点放在取消按钮，遮罩点击不应直接关闭。
- 确认弹窗按钮文案应表达结果，例如“退出登录 / 继续使用”，禁止只使用“确定 / 取消”造成误解。
- 修改密码页必须在输入区域附近展示密码规则，不依赖用户失败提交后才知道规则；规则状态使用轻量勾选反馈，不使用大面积高亮。
- 用户可见错误统一使用中文、动作导向和短句；错误码、堆栈、Provider 原始英文响应和 SQL 信息不得直接展示。
- 网络、鉴权、权限、资源不存在、冲突、服务器错误和 AI Provider 错误必须有统一中文兜底文案。
