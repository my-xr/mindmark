# 09 权限与安全设计

## 1. 设计目标

- 确保教师、TA、学生、管理员的权限边界清晰。
- 确保学生数据隔离，避免越权访问。
- 确保考试、批改、成绩发布等关键操作可审计。
- 确保 AI API Key 和敏感数据按企业级要求保护。

## 2. RBAC 角色

| 角色 | 权限概述 |
| --- | --- |
| ADMIN | 管理用户、角色、课程、班级、系统配置和审计日志。 |
| TEACHER | 管理自己课程下的题库、试卷、考试、批改、成绩和复盘。 |
| TA | 在授权课程 / 考试范围内协助题库维护和批改复核。 |
| STUDENT | 参加被分配的考试，查看自己的答卷、成绩和反馈。 |

## 3. 权限矩阵草案

| 功能 | ADMIN | TEACHER | TA | STUDENT |
| --- | --- | --- | --- | --- |
| 用户管理 | 全部 | 无 | 无 | 无 |
| 课程 / 班级管理 | 全部 | 自己课程 | 授权查看 | 所属班级查看 |
| 题库查看 | 全部 | 自己 / 授权 | 授权 | 无 |
| 题目编辑 | 全部 | 自己 / 授权 | 授权 | 无 |
| AI 出题 | 配置级 | 自己课程 | 授权 | 无 |
| 组卷 | 全部 | 自己课程 | 授权 | 无 |
| 发布考试 | 全部 | 自己课程 | 通常无，除非授权 | 无 |
| 参加考试 | 无 | 无 | 无 | 被分配考试 |
| 批改复核 | 全部 | 自己考试 | 授权 | 无 |
| 发布成绩 | 全部 | 自己考试 | 通常无，除非授权 | 无 |
| 查看成绩 | 全部 | 自己考试 | 授权 | 仅自己 |
| 申诉处理 | 全部 | 自己考试 | 授权 | 仅提交 / 查看自己申诉 |
| 审计日志 | 全部 | 自己课程关键日志 | 无或有限 | 无 |

## 4. 数据隔离规则

- 学生只能访问自己的考试、答卷、成绩、反馈和申诉。
- 教师只能访问自己创建或被授权的课程、班级、题库、考试数据。
- TA 只能访问被明确授权的课程、考试或批改任务。
- 管理员可访问全局配置和审计，但敏感字段仍需脱敏展示。

## 5. 关键操作审计

必须记录审计日志的操作：登录/登录失败、创建/发布/撤回/取消考试、修改已发布考试相关配置、AI 题目接受/编辑/拒绝、AI 批改结果接受或人工调整分数、发布成绩、处理成绩申诉、修改角色/权限/课程授权、修改大模型 Provider 配置或 API Key。

审计日志建议字段：`id`、`actorId`、`action`、`resourceType`、`resourceId`、`before`、`after`、`reason`、`ip`、`userAgent`、`createdAt`。

## 6. 敏感信息保护

- 禁止在代码中硬编码真实 API Key。
- 用户 API Key 必须加密存储。
- 页面展示 API Key 时只允许脱敏展示。
- 大模型调用必须记录调用人、用途、模型、耗时、结果状态和错误信息。
- 学生成绩、答卷和个人信息接口必须鉴权和鉴权后过滤。

## 7. 考试安全边界

当前重点：L1（禁复制、禁右键、全屏提示）与 L2（切屏检测、题序随机、选项随机）。L3（IP 白名单、单点登录、同卷不同题、数值参数化、行为审计回放）暂缓。

## 8. 后续维护规则

新增角色、权限或敏感数据前，必须更新本文档和测试验收清单。

## Iteration 14 安全设计占位说明

本轮完成的是开发阶段最小鉴权闭环，不等价于正式安全方案：

- token 格式为 `dev-token-{userId}`，没有签名、过期时间、刷新机制和撤销列表。
- 密码字段未落库、未哈希，本轮登录仅用于联调演示账号。
- 后端尚未使用 Spring Security 对业务接口做统一拦截。
- 前端已具备登录、会话恢复、退出与 401/网络错误的页面级承接基础。

下一步安全设计必须补齐：密码哈希、登录失败限流、JWT/Session 选型、RBAC 权限注解/过滤器、审计日志、生产环境禁用开发 Header。
## Iteration 15 前置确认：考试账号安全补充

- 当前 `dev-token-*` 登录仅用于本地联调，不能用于真实考试。
- 学生名单导入创建账号时，初始密码规则为“学号后 6 位”；若学号不足 6 位，需在实现前明确补零或拒绝导入策略，默认建议拒绝并给出行级错误。
- 初始密码、教师/TA 重置后的密码不得明文落库，只保存密码哈希；接口响应不得返回明文密码。
- 学生首次登录或被重置密码后，`must_change_password=true`，必须完成改密后才能访问考试列表、答题页、成绩页等学生业务页面。
- 教师/TA 只能重置其授权课程/班级内学生密码；管理员可全局重置。所有重置操作必须二次确认并写入审计日志。
- 密码修改、密码重置、名单导入、登录成功/失败均属于安全审计事件。

## Iteration 15 安全补充：账号密码与首次改密

- 密码必须使用哈希存储；当前 P0 使用 PBKDF2，格式为 `pbkdf2:iterations:salt:hash`。
- 学生导入创建账号后 `must_change_password=true`，首次登录必须修改密码。
- 教师/助教/管理员重置学生密码后同样设置 `must_change_password=true`。
- 前端路由守卫必须在 `mustChangePassword=true` 时阻止访问业务页面，只允许进入 `/auth/change-password`。
- 当前 `dev-token-*` 仅用于开发联调，不满足生产安全要求；后续必须引入正式 Token/Session、服务端鉴权拦截与班级级授权。
- 名单导入、重置密码、登录失败等操作必须进入审计日志，日志不得包含明文密码。

## Iteration 16 安全设计更新：Sa-Token 正式鉴权

- 本项目后端鉴权采用 Sa-Token Spring Boot 3 Starter，不采用 Spring Security。
- Token 读取规范：前端统一发送 `Authorization: Bearer <opaque-token>`；后端配置 `token-name=Authorization`、`token-prefix=Bearer`。
- 统一拦截规则：`/api/v1/auth/login`、`/api/v1/system/health` 公开，其余 `/api/v1/**` 默认执行 `checkLogin()`。
- 角色权限：通过 Sa-Token `StpInterface` 从 `auth_user_role` 动态加载 `ADMIN/TEACHER/TA/STUDENT`；账号管理接口要求 `ADMIN/TEACHER/TA`。
- 数据权限：学生账号管理增加班级范围校验，`ADMIN` 可全局管理，`TEACHER/TA` 必须存在 `teacher_class_assignment` 授权。
- 密码策略：新密码至少 8 位且包含字母和数字，不能与旧密码、用户名或邮箱相同；名单导入/重置仍生成学号后 6 位初始密码，并强制首次改密。
- 异常治理：未登录/会话过期映射 `MM-401-001`，角色或班级越权映射 `MM-403-001`，避免向前端泄漏内部鉴权细节。
## Iteration 17 安全策略补充：账号治理与登录失败锁定

- 鉴权继续采用 Sa-Token，不引入 Spring Security。
- `/api/v1/admin/**` 统一要求登录态和 `ADMIN` 角色，角色校验由 Sa-Token `checkRole` 执行。
- 连续登录失败策略：同一账号密码错误累计 5 次后锁定 15 分钟；锁定期间继续登录会被拒绝并记录 `LOGIN/FAILED` 审计。
- 成功登录、管理员启用账号、管理员解锁账号均会清空 `failed_login_count` 与 `locked_until`。
- 禁用账号时后端调用 Sa-Token 注销目标账号会话，降低“状态已禁用但旧会话仍可用”的风险。
- 审计范围覆盖登录、登出、改密、账号启停、角色变更、解锁、班级授权新增/更新/删除。
- 防自锁策略：管理员不能禁用自身账号，也不能移除自身 `ADMIN` 角色。

## 2026-09-20：Sa-Token 运行态安全边界复核与收敛

本轮以真实 HTTP 请求和后端代码双重检查为准，不再把“能登录”当作权限验收通过。

### 已修复的边界问题

1. **停用账号旧 Token**
   - `/api/v1/**` 的统一拦截除了 `checkLogin()`，还会查询 `auth_user.status`；
   - 用户不存在返回 `401`，账号为 `DISABLED` 返回 `403`；
   - 当前 Token 会立即注销；
   - Sa-Token 角色列表对非 `ACTIVE` 用户返回空，避免旧角色缓存继续生效。
2. **学生访问教师资源**
   - 学生不能访问题库列表/详情、试卷列表、考试管理列表、成绩批次、批改中心、复盘分析和学生名单模板；
   - 教师/助教/管理员接口统一使用 Sa-Token `checkRoleOr(ADMIN, TEACHER, TA)`，服务层仍保留二次校验。
3. **学生试卷答案泄漏**
   - 学生只能访问自己班级已关联考试的试卷；
   - 学生试卷响应保留作答所需的题干、选项、题型、分值等字段；
   - `answer`、`analysis`、`scoringPoints`、出题人、审核人、审核意见和审核动作均不返回。
4. **课程数据范围**
   - 非管理员教师/助教只能访问 `teacher_class_assignment` 授权班级关联的课程；
   - 题库、试卷、AI 出题任务的课程范围在服务层校验；
   - 异步 AI 任务使用提交者 `teacherId` 重新校验课程范围，不能因为脱离 HTTP 请求而绕过权限。
5. **前端伪造身份请求头**
   - `X-MindMark-User-Id`、`X-MindMark-Roles` 不参与身份和角色决策；
   - 真实身份只来自 Sa-Token 当前会话。

### 关键接口边界

| 接口类型 | ADMIN/TEACHER/TA | STUDENT |
| --- | --- | --- |
| 题库、试卷、考试管理列表 | 允许，按课程/班级范围过滤 | `403` |
| 学生考试详情 | 管理端按班级范围；学生仅本人班级考试 | 允许 |
| 学生考试试卷 | 管理端完整字段；学生本人考试且脱敏 | 允许脱敏字段 |
| 批改、成绩批次、复盘、审计查询 | 允许，按考试班级范围过滤 | `403` |
| 答题草稿、交卷、安全事件上报 | 禁止代替学生操作 | 仅本人答卷/本人考试 |
| 学生成绩反馈 | 不作为学生端接口使用 | 仅本人已发布成绩 |

- 已完成按 IP、账号维度的 Redis 登录限流；生产仍需补充设备维度、验证码、WAF 或其他风控策略；
- 密码修改、管理员重置密码后增加全账号会话失效/Token 版本机制；

## 2026-09-24：安全边界补强与生产前置条件

本轮继续以“后端真实会话 + 角色策略 + 数据范围”作为安全边界，前端页面和请求头均不视为可信来源。

### 已完成

1. **角色集合约束**
   - `ADMIN` 不允许与其他角色混用；
   - `STUDENT` 不允许与 `TEACHER/TA/ADMIN` 混用；
   - 空角色、无效角色集合无法登录，已有会话在统一拦截器中会被注销；
   - Sa-Token 的角色列表只对 ACTIVE 且角色集合有效的账号返回。
2. **考试创建数据边界**
   - 试卷课程必须属于当前教师/助教的课程范围；
   - 目标班级必须属于试卷课程，阻断跨课程组考；
   - 新考试保存 `created_by_user_id`，不再只依赖可变的教师姓名。
3. **AI 批改配置隔离**
   - AI 批改任务优先使用考试创建人的稳定用户 ID；
   - 历史考试兼容按用户 ID、用户名、邮箱、姓名解析；
   - 解析不到有效的 ACTIVE 教师/助教/管理员时，任务拒绝执行，不回退到不确定的账号。
4. **编程题评测归属**
   - 提交前同时校验考试、答卷、学生所有权；
   - 编程题必须属于当前考试试卷，不能仅凭题目 ID 跨试卷提交。
5. **登录限流**
   - Redis 原子计数器按“账号”和“来源 IP”双维度限制；
   - 默认窗口 5 分钟，账号最多 10 次，IP 最多 50 次；
   - Redis Key 只保存 SHA-256 摘要，不保存明文账号或 IP；
   - Redis 不可用时登录安全服务 fail-closed，不绕过限流；
   - 超限返回 `MM-429-001`，原有数据库 5 次密码失败锁定 15 分钟仍保留。
6. **生产密钥强制**
   - `application-prod.yml` 强制 `mindmark.security.strict-secrets=true`；
   - AI 加密密钥必须由环境变量注入且至少 32 个字符、不能使用本地默认值；
   - MinIO 生产环境不能使用 `minioadmin/minioadmin123` 默认凭据；
   - 数据库、Redis、MinIO 生产配置改为必需环境变量。

### 数据库迁移

- `V28__security_role_and_exam_owner_hardening.sql`：清理历史混合角色并补充考试创建人稳定 ID。
- `V29__normalize_grading_ai_job_owner.sql`：把历史 AI 批改任务中的教师姓名/用户名归一到用户 ID。

### 尚未替代的生产安全能力

- Redis 限流不等同于设备指纹、验证码、WAF 或分布式风控；
- 当前仍应在部署层配置 HTTPS、可信代理 IP 解析、密钥管理、数据库最小权限和审计日志留存；
- 生产发布前必须使用独立的 TEACHER、TA、STUDENT 账号完成跨课程、跨班级拒绝用例，不能只用开发账号。

## 2026-10-22：生产前安全检查与可信代理边界

- 登录限流读取客户端地址时，只有 `mindmark.security.trusted-proxy-cidrs` 配置范围内的反向代理才可信；直接来自公网或未配置代理的请求会忽略 `X-Forwarded-For` 与 `Forwarded`，避免请求头伪造限流来源。
- 生产启动由 `ProductionConfigurationValidator` 进行 fail-fast 检查：数据库、Redis、MinIO 不得指向本机，不能使用本地默认凭据，AI 加密密钥必须由环境注入且至少 32 位，OpenAPI/Swagger 关闭且 Actuator 只暴露 `health`。
- `scripts/api-smoke/run-authz-security-smoke.ps1` 支持 `-RequireIndependentRoles`、`-TaUsername`、`-TaPassword`、`-AssignedCourseId` 和 `-OutOfScopeCourseId`，用于以独立 TEACHER/TA/STUDENT 账号验证角色集合和跨课程拒绝；不应使用同时拥有 ADMIN 的开发账号替代。
- `scripts/api-smoke/run-login-rate-limit-smoke.ps1` 默认验证第 11 次请求为 `429`；在测试窗口过期后传入 `-RecoveryWaitSeconds`，额外验证窗口恢复后请求回到业务层 `401`。
