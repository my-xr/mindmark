# 20 后端系统框架设计

## 1. 文档目的

本文档定义 MindMark 后端主项目 `apps/mindmark-server` 的工程骨架、模块边界、数据访问规范、配置规则、OpenAPI 契约落地方式和质量门禁。后续后端业务开发必须同步更新本文档、`08_API设计规范.md`、`19_后端接口契约准备.md` 和 `14_迭代计划与复盘.md`。

## 2. 当前阶段结论

- Iteration 7 起正式创建后端主项目：`apps/mindmark-server`。
- 后端采用 **Spring Boot 模块化单体**，先承载考试系统闭环，暂不拆微服务。
- 当前已完成后端骨架、健康检查、统一响应 / 错误模型、基础配置、模块包结构、Flyway 基线迁移和静态 OpenAPI 契约。
- Iteration 8 已落地题库与组卷 P0 业务接口；考试、答卷、批改、成绩、复盘等接口仍以 OpenAPI 契约为后续实现基准。
- 数据库访问层统一采用 **Spring Data JPA + Hibernate ORM + HikariCP 连接池**，表结构由 Flyway 管理，禁止 Hibernate 自动建表。

## 3. 技术栈

| 分类 | 技术 | 说明 |
| --- | --- | --- |
| 语言 | Java 21 | 与本地 JDK 对齐，利于长期维护。 |
| 框架 | Spring Boot 3.3.x | Web MVC + Validation + Actuator。 |
| ORM / Repository | Spring Data JPA + Hibernate | 后端统一 ORM 选型，不混用多套数据访问框架。 |
| 数据库连接池 | HikariCP | Spring Boot 默认连接池，参数通过环境变量覆盖。 |
| 数据库 | PostgreSQL | 本地默认 `localhost:5432`，开发用户名 / 密码为 `postgres/123456`；生产必须通过环境变量覆盖。 |
| 缓存 | Redis | 本地默认 `localhost:6379`，无密码；当前阶段仅完成连接配置，暂未实现缓存业务。 |
| 数据迁移 | Flyway | 所有数据库结构变更必须通过 migration 文件记录。 |
| API 文档 | springdoc-openapi + 静态 YAML | 运行时 Swagger UI 与版本化静态契约并存。 |
| 构建 | Maven | 后端子项目独立 Maven 构建，根目录通过 pnpm scripts 代理。 |

## 6. 配置规范

`application.yml` 使用环境变量覆盖默认值：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `MINDMARK_SERVER_PORT` | `8080` | 后端端口 |
| `MINDMARK_DB_HOST` | `localhost` | PostgreSQL 主机 |
| `MINDMARK_DB_PORT` | `5432` | PostgreSQL 端口 |
| `MINDMARK_DB_NAME` | `mindmark` | 本地业务库；不要使用 PostgreSQL 管理默认库 `postgres` |
| `MINDMARK_DB_USERNAME` | `postgres` | 数据库用户 |
| `MINDMARK_DB_PASSWORD` | `123456` | 本地开发数据库密码；生产环境必须覆盖 |
| `MINDMARK_DB_POOL_MAX_SIZE` | `10` | HikariCP 最大连接数 |
| `MINDMARK_DB_POOL_MIN_IDLE` | `2` | HikariCP 最小空闲连接 |
| `MINDMARK_REDIS_HOST` | `localhost` | Redis 主机 |
| `MINDMARK_REDIS_PORT` | `6379` | Redis 端口 |
| `MINDMARK_AI_QUESTION_PROVIDER` | `OPENAI` | AI 出题默认 Provider，可选 `OPENAI` / `ANTHROPIC` |
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` | OpenAI-compatible Chat Completions 地址 |
| `OPENAI_MODEL` | `gpt-4.1-mini` | OpenAI 出题模型 |
| `OPENAI_API_KEY` | 空 | OpenAI 全局兜底 Key，仅环境变量注入 |
| `ANTHROPIC_BASE_URL` | `https://api.anthropic.com/v1` | Anthropic Messages API 地址 |
| `ANTHROPIC_MODEL` | `claude-3-5-sonnet-latest` | Anthropic 出题模型 |
| `ANTHROPIC_API_KEY` | 空 | Anthropic 全局兜底 Key，仅环境变量注入 |
| `KIMI_BASE_URL` | `https://api.moonshot.cn/v1` | 历史兼容/讲评稿遗留 Provider 地址 |
| `KIMI_API_KEY` | 空 | 历史兼容/讲评稿遗留 Key，仅环境变量注入 |

敏感信息规则：

- 不得将真实 API Key、数据库生产密码、JWT 密钥写入仓库。
- 用户本地提供的 OpenAI / Anthropic API Key 仅允许通过教师个人加密配置、运行时环境变量或 `.env.local`（已被 `.gitignore` 忽略）注入，不能写入 `application.yml`、README、OpenAPI 或任何文档；Kimi 仅作为讲评稿历史兼容配置保留。
- 前端不得直接调用外部 AI；所有 AI 能力必须经后端 Provider 封装、鉴权、审计和中文内容校验。

### 6.1 三种启动方式

| 场景 | 数据库 | 启动方式 | 说明 |
| --- | --- | --- | --- |
| 本机依赖服务 | `localhost:5432/mindmark`，`postgres/123456` | `pnpm server:run` | 读取 `application.yml` 的本地默认值，也可用环境变量覆盖。 |
| Docker 依赖服务 | `localhost:54321/mindmark`，`mindmark/mindmark_dev_password` | `docker compose -f apps/mindmark-server/docker-compose.yml up -d`，再设置 `MINDMARK_DB_PORT=54321` 等变量后运行后端 | Compose 仅启动 PostgreSQL、Redis、MinIO，不启动 Java 服务。 |
| 生产部署 | 由平台提供 | `$env:SPRING_PROFILES_ACTIVE='prod'; pnpm server:run` | `application-prod.yml` 不提供本地默认凭据，缺失或使用默认密钥时启动失败。 |

本地变量模板位于 `apps/mindmark-server/.env.example`。Spring Boot 不会自动读取该文件，PowerShell、IDE 或部署平台需要显式导入变量；模板只包含开发凭据，不得复制到生产环境。生产启动前可运行 `scripts/run-production-check.ps1` 做环境变量、健康检查和质量门禁检查。

## 7. API 契约落地

- 静态契约文件：`apps/mindmark-server/openapi/mindmark-api.yaml`。
- 契约覆盖 `19_后端接口契约准备.md` 中列出的 P0/P1 接口。
- 前端 service 迁移真实接口时，以该 YAML 的路径、请求体、响应结构和错误码为准。
- 运行后可访问 `http://localhost:8080/swagger-ui/index.html` 查看运行时接口文档；静态契约仍作为版本化基准。

Iteration 8 已实现接口：

| 接口 | 模块 | 说明 |
| --- | --- | --- |
| `GET /api/v1/questions` | question | 题库分页列表，支持关键词、题型、难度、状态、来源、知识点筛选。 |
| `GET /api/v1/papers` | paper | 试卷分页列表，返回试卷和题目结构。 |

## 8. 数据库迁移规则

1. 所有表结构变更必须新增 `src/main/resources/db/migration/V{序号}__{说明}.sql`。
2. 不允许在业务代码中隐式建表。
3. `spring.jpa.hibernate.ddl-auto` 固定为 `none`，Flyway 是唯一建表来源。
4. 迁移文件必须可重复审查、可追溯，并同步更新 `07_领域模型与数据字典.md`。
5. 同一版本号只能存在一个 Flyway migration 文件，禁止出现重复 `V2__*.sql`。

已新增 migration：

- `V1__init_contract_schema.sql`：`audit_operation_log`、`api_contract_snapshot`。
- `V2__question_and_paper_schema.sql`：`question`、`question_knowledge_point`、`paper`、`paper_question` 及 P0 演示种子数据。

## 9. 数据访问分层规范

| 层级 | 规则 |
| --- | --- |
| Controller | 只负责 HTTP 入参、校验和统一响应包装，不直接访问 Repository。 |
| Service | 承载业务规则、事务边界、状态校验、冲突处理。 |
| Repository | 基于 Spring Data JPA，必要时使用 Specification、EntityGraph、JPQL 或 native query。 |
| Entity | 只表达持久化模型，不直接作为 API 响应返回。 |
| DTO / Response | 面向前端契约，复杂 JSON 字段在 Mapper 层转换。 |

## Iteration 10 增量：批改与成绩模块设计

### 模块划分

- `modules/grading`：承载批改任务、批改明细、客观题自动批改、教师复核。
- `modules/score`：承载考试成绩汇总、成绩发布、学生成绩报告快照读取。

### 分层约定

每个模块继续遵循 `domain`、`dto`、`repository`、`service`、`web` 分层：

- `domain`：JPA Entity 与枚举。
- `repository`：Spring Data JPA Repository，必要时使用 `@EntityGraph` 控制详情加载。
- `service`：事务边界、状态流转、自动批改规则、成绩排名与发布逻辑。
- `web`：REST Controller，仅处理参数绑定与统一响应包装。

### 数据库约定

- 继续使用 Flyway 管理结构变更，本轮新增 `V4__grading_and_score_schema.sql`。
- 禁止依赖 Hibernate 自动建表，`ddl-auto` 保持 `none`。
- `score_report` 作为发布快照表，允许重复发布时按 `(exam_id, student_id)` 更新。

### 外部基础设施

本轮暂不把 MinIO 纳入批改 P0 主链路。MinIO 后续用于 AI 讲评稿、批改附件、导出文件等 artifact 归档；凭据必须通过环境变量配置，不写入仓库。

## Iteration 13 补充：开发态鉴权占位模块

### 模块结构
```text
com.mindmark.server.modules.auth
├─ domain        # AuthUserEntity、RoleCode、UserStatus
├─ dto           # CurrentUserResponse
├─ repository    # AuthUserRepository
├─ service       # AuthContextService
└─ web           # AuthController
```

### 设计原则
- 当前阶段不引入正式安全框架拦截链，先提供前端真实接口联调所需的“当前用户上下文”。
- 用户与角色使用 PostgreSQL 持久化，避免纯内存 Mock 与真实接口模式割裂。
- `AuthContextService` 支持请求头覆盖，便于本地模拟不同角色；默认回退到演示教师用户。
- 正式鉴权上线时，应将请求头覆盖替换为 Token / Session / SSO 解析，并把用户上下文注入各业务服务。

### 数据库迁移
- `V5__auth_placeholder_schema.sql`
  - `auth_user`
  - `auth_role`
  - `auth_user_role`
- 演示种子：`u-teacher-001`，角色 `ADMIN`、`TEACHER`、`TA`、`STUDENT`，学生映射 `student-001`。

## Iteration 14 运行态与鉴权框架补充

### 数据库运行库
本地开发默认数据库从 `postgres` 调整为 `mindmark`：

```yaml
spring.datasource.url: jdbc:postgresql://${MINDMARK_DB_HOST:localhost}:${MINDMARK_DB_PORT:5432}/${MINDMARK_DB_NAME:mindmark}
```

原因：`postgres` 应作为管理/默认库保留，业务表、Flyway 历史与演示数据统一进入 `mindmark` 库。

### Auth 模块当前边界
- `AuthController` 暴露 `/api/v1/auth/login`、`/api/v1/auth/me`、`/api/v1/auth/logout`。
- `AuthContextService` 负责演示用户解析、开发 token 生成与 `Authorization` Header 解析。
- `AuthUserRepository` 支持按 id 与 email 查询。
- 当前不启用正式 filter chain；业务接口仍未强制鉴权，待后续 Spring Security 迭代收口。
## Iteration 16 框架更新：Sa-Token 鉴权栈

- 鉴权框架：`cn.dev33:sa-token-spring-boot3-starter`，版本由 `sa-token.version` 统一管理。
- 会话存储：引入 `sa-token-redis-jackson`，使用本地/环境 Redis 承载登录态，避免进程内 Session 在重启后丢失。
- Web 拦截：`SaTokenConfig` 注册 `SaInterceptor`，对 `/api/v1/**` 默认 `checkLogin()`，仅放行登录与健康检查。
- 角色加载：`SaTokenPermissionService` 实现 `StpInterface`，从 `auth_user_role` 动态加载角色，服务层可使用 Sa-Token 角色能力与领域数据权限能力组合校验。
- 账号领域硬化：新增 `teacher_class_assignment` 作为教师/助教班级范围授权表；账号治理服务在角色校验后继续做班级范围校验。
- 前端契约：真实接口模式只依赖 `Authorization: Bearer <token>`，不再依赖 `X-MindMark-User-Id` 或 `X-MindMark-Roles`。
## Iteration 17 后端设计补充：账号治理模块

- 模块位置：继续放在 `modules.auth` 下，作为认证授权域的管理员治理子能力，避免拆散用户、角色、审计、班级授权聚合。
- 持久化：继续采用 Spring Data JPA + Hibernate ORM + HikariCP；新增查询使用 `JpaSpecificationExecutor` 支持动态筛选。
- 会话治理：禁用账号时调用 Sa-Token 目标账号登出；解锁只清理失败计数与锁定时间，不修改密码。
- 事务边界：账号启停、角色替换、解锁、班级授权 upsert/delete 均为事务操作，并在同一事务内写入 `auth_audit_log`。
- 迁移策略：Flyway V8 仅执行 additive schema change，不清空历史数据，不触碰 `postgres` 默认库，继续使用 `mindmark` 数据库。
