# 10 AI 能力与人工审核规范

## 1. 设计原则

1. AI 优先处理重复性工作，但不绕过人工审核。
2. 大模型接入必须抽象 Provider / Adapter，避免绑定单一厂商。
3. 所有 AI 输出必须可解释、可追溯、可拒绝或编辑。
4. 用户 API Key 必须加密存储、脱敏展示、权限隔离和调用审计。
5. AI 失败时系统必须有人工兜底流程。

## 2. MVP AI 能力范围

| 能力 | 优先级 | 说明 |
| --- | --- | --- |
| AI 题目生成 | P0 | 按知识点、题型、难度生成题目。 |
| 得分点拆解 | P0 | 主观题和编程题必须输出得分点。 |
| 答案校验 | P1 | 校验答案合理性，提示风险。 |
| 相似题查重 | P1 | 展示相似风险，后续接入向量检索。 |
| 简答题 AI 预批改 | P0 | 要点匹配、评分、评语、置信度。 |
| 编程题 AI 预批改 | P0 | 静态分析、得分点判定、评语；不做代码沙箱。 |
| AI 试卷讲评稿 | P1 | 基于考试结果生成教师可编辑讲评稿。 |
| 错因归纳 | P1 | 学生侧反馈和知识点建议。 |

## 3. Provider / Adapter 抽象

建议抽象层：

```text
AiProvider
├─ generateQuestions(request)
├─ validateAnswer(request)
├─ gradeShortAnswer(request)
├─ gradeProgrammingAnswer(request)
├─ generateExamReview(request)
└─ summarizeMistakes(request)
```

Provider 配置字段：`providerCode`、`baseUrl`、`model`、`encryptedApiKey`、`enabled`、`ownerScope`。AI 出题页面只选择 Provider，服务器地址、模型和 Key 在教师个人配置中维护。个人配置页必须提供模型连接测试能力：使用表单中的 baseUrl/model/apiKey 或已保存 Key 发起轻量调用，只返回成功状态、耗时和短响应预览，不落库、不记录明文 Key。OpenAI-compatible Provider 需要兼容 Moonshot/Kimi 等模型网关，请求体默认不发送 temperature，避免部分模型仅允许固定 temperature 导致连接测试或题目生成失败。

## 4. AI 出题输出要求

AI 生成题目至少包含：题型、题干、选项（如适用）、标准答案/参考答案、解析、知识点、难度、建议分值、得分点清单、风险提示。

## 5. AI 批改输出要求

AI 批改至少包含：AI 建议得分、得分点逐项命中情况、扣分原因、评语、置信度、需要人工重点复核的风险标签。

## 6. 人工审核规则

| 场景 | 人工操作 |
| --- | --- |
| AI 生成题目 | 接受、编辑后接受、拒绝、重新生成。 |
| 简答题批改 | 接受 AI 分数、调整分数、编辑评语、标记异常。 |
| 编程题批改 | 查看静态分析和得分点判定，调整分数和评语。 |
| 成绩发布 | 发布前检查异常和未复核项，确认后发布。 |

## 6.1 AI 出题候选状态与风险标签

### 审核状态

| 状态 | 说明 | 可选操作 |
| --- | --- | --- |
| PENDING | AI 候选题待人工审核 | 接受、编辑后接受、拒绝、重新生成 |
| ACCEPTED | 教师确认后可入库 | 后续进入题库管理 |
| EDITED_ACCEPTED | 教师编辑题干 / 答案 / 得分点后入库 | 后续进入题库管理 |
| REJECTED | 教师拒绝该候选题 | 不进入题库，仅保留审计记录 |

### 风险标签

| 标签 | 说明 | 审核重点 |
| --- | --- | --- |
| LOW_CONFIDENCE | AI 置信度偏低 | 优先复核题干、答案和得分点 |
| AMBIGUOUS_STEM | 题干疑似歧义 | 明确限定条件，避免多解 |
| ANSWER_NOT_UNIQUE | 答案可能不唯一 | 检查标准答案和评分口径 |
| KNOWLEDGE_MISMATCH | 知识点可能不匹配 | 校正知识点归属 |
| SCORING_POINT_WEAK | 得分点偏弱 | 补充可执行、可判定的得分点 |

前端 Mock 阶段必须显式展示置信度、风险标签和人工审核状态，避免用户误以为 AI 内容已自动入库。


## 6.2 AI 讲评稿输出与人工确认规则

AI 讲评稿用于帮助教师快速组织考后讲评，不是面向学生的自动发布内容。

AI 讲评稿至少包含：考试概况、均分与通过率说明、薄弱知识点、低得分率题目拆解、学生分层建议、讲评提纲、正文草稿、置信度、风险标签和生成时间。

| 状态 | 说明 | 可选操作 |
| --- | --- | --- |
| DRAFT | AI 初始草稿，仅供教师参考 | 查看、编辑、重新生成、确认 |
| REVIEWING | 重新生成后等待教师确认 | 编辑、确认、再次重新生成 |
| APPROVED | 教师已确认讲评稿 | 查看确认内容，后续可进入发布 / 归档流程 |

人工确认要求：

- 教师必须核对统计口径、低分题解释和知识点建议，必要时编辑草稿正文。
- 讲评稿存在“未完全复核”“薄弱知识点需人工确认”等风险标签时，应优先核对原始答卷和批改结果。
- 禁止将 AI 讲评稿不经教师确认直接发布给学生或作为最终教学结论。

## 7. AI 调用审计

AI 调用记录建议字段：`id`、`providerCode`、`model`、`useCase`、`actorId`、`inputHash`、`outputHash`、`status`、`latencyMs`、`tokenUsage`、`errorMessage`、`createdAt`。

## 8. 禁止事项

- 禁止将 AI 题目不经审核直接入库。
- 禁止将主观题 AI 评分不经策略确认直接发布。
- 禁止在代码、文档示例或 Mock 中放置真实 API Key。
- 禁止把 AI 输出作为不可修改的最终结论。

## 9. 后续维护规则

新增 AI 能力时必须补充：输入、输出、审核点、失败兜底、审计字段和权限边界。

## Round 4：AI 讲评稿人工审核规则

- P0 阶段讲评稿使用确定性本地模板生成，保留 `provider`、`prompt_snapshot`、`confidence` 字段，为后续真实 Provider 接入预留审计链路。
- AI 讲评稿状态流转：`DRAFT`（初始草稿）→ `REVIEWING`（重新生成后待确认）→ `APPROVED`（教师确认）。`FAILED` 预留给外部模型调用失败场景。
- 教师确认前必须核对：考试统计数字、低分题目、知识点建议、课堂活动安排和对学生的表述风险。
- 导出的讲评稿优先使用 `teacher_edited_content`；若未编辑则使用 AI 初稿正文。

## 2026-07-19 AI 出题真实链路规范补充

- AI 出题链路采用 LangGraph 编排，不在 Controller 中直接拼接完整业务流程。
- P0 图节点固定为：`validate_input`、`resolve_course`、`generate_with_ai`、`persist_questions`。
- AI 出题 Provider 不绑定 Kimi，当前支持 `OPENAI` 与 `ANTHROPIC`；调用必须优先使用当前教师个人 Key，个人 Key 不存在时才允许使用对应全局环境变量兜底。
- 模型输出必须要求严格 JSON，并在服务端再次校验题型、五级难度、答案、解析、选项/评分点结构、题目数量和中文内容；英文题干/解析不得入库。
- AI 生成题目默认进入 `PENDING_REVIEW`，不得绕过教师审核直接作为正式 ACTIVE 题目进入组卷。
- Prompt、模型返回和失败原因后续应进入 AI 任务/审计表；当前阶段不记录明文 API Key。
### 4.4 真实生成链路容错

AI 出题审核的真实生成链路必须区别于连接测试：连接测试只验证模型可达，生成链路需要完成“模型生成 -> JSON 解析 -> 中文校验 -> 写入待审核题库”。OpenAI-compatible 模型生成题目时需要支持一次自动重试：当模型返回空 content、输出 token 不足、或返回非合法题目 JSON 时，后端应提升输出 token 预算或强化 JSON-only 提示后重试；LangGraph 工作流不得吞掉底层错误，需要向前端透传可定位的失败原因。
### 4.5 LangGraph 状态约束与本次修复

- LangGraph4j 的 `Channel` 默认值不得返回 `null`，否则图初始化阶段会在构造初始状态 Map 时抛出 NPE；输入字段必须提供非空哨兵值或拆分为基础类型字段。
- 放入 LangGraph 状态中的对象必须可序列化，当前 AI 出题工作流涉及的 `AiQuestionGenerateRequest`、`QuestionCreateRequest`、`QuestionResponse` 与课程实体已显式实现 `Serializable`。
- 已新增 `LangGraphQuestionGenerationServiceTest`，覆盖真实 payload 下图初始化不再因空默认值或状态序列化失败中断。
### 4.6 AI 生成超时策略

- AI 题目生成属于慢接口，前端不得使用全局 10 秒超时；真实生成接口默认前端超时为 120 秒，连接测试默认 45 秒。
- 后端 Provider 调用默认超时为 90 秒，可通过 `MINDMARK_AI_QUESTION_TIMEOUT_MS` 调整。
- 若生成仍超过同步等待窗口，应进入异步任务化：提交任务立即返回 `taskId`，前端轮询进度，完成后刷新待审核题目列表。
## 4.7 AI 出题异步任务规范（2026-07-20）

AI 出题真实链路必须异步化，避免模型响应慢导致前端 10 秒请求超时。

- 提交任务：教师在 AI 出题审核页提交生成参数，后端创建 `ai_question_generation_task` 并返回 `taskId`。
- 后台执行：独立线程池执行 LangGraph 工作流，任务状态从 `PENDING` → `RUNNING` → `SUCCEEDED/FAILED`。
- 轮询进度：前端轮询任务接口展示“已提交、生成中、完成、失败”状态。
- 入库规则：生成成功后写入题库的题目必须是 `AI + PENDING_REVIEW`，不得直接 `ACTIVE`。
- 失败可见：Provider 超时、JSON 解析失败、中文校验失败、Key 缺失等错误必须落入任务 `errorMessage` 并返回给前端。
- 并发治理：同一教师同一时间只允许一个运行中 AI 出题任务。
- 审计留痕：任务提交、成功、失败必须写入审计日志；API Key 不得写入日志、文档或任务表。
## 4.8 AI 主观题/编程题批改工作流（2026-07-21）

本阶段采纳“AI 智能体辅助批改”方案，但明确不做 Sandbox / OJ 真实执行判题；编程题由 AI 基于题干、参考答案、评分点和学生代码进行静态阅读评分，并默认保留教师复核入口。

- 后端工作流文件：`apps/mindmark-server/src/main/java/com/mindmark/server/modules/grading/service/LangGraphGradingWorkflow.java`。
- 工作流版本：`grading-langgraph-v20260721`。
- 图节点：`validate_input` → `extract_rubric` → `route_question_type` → `call_ai_scorer` → `quality_gate`。
- 支持题型：`SHORT_ANSWER`、`ESSAY`、`CASE_ANALYSIS`、`PROGRAMMING`。
- Provider：沿用教师个人配置中的 OpenAI-compatible / Anthropic 配置，不在批改页面配置 Key、baseUrl 或 model。
- 输出要求：Provider 必须返回 JSON，至少包含 `score`、`correct`、`confidence`、`needsReview`、`comment`；服务端会做 JSON 提取、分数夹取、置信度夹取和低置信度复核标记。
- 兜底策略：AI Provider 未配置、超时、返回空内容或非合法 JSON 时，不阻断批改闭环，保留系统基线分并提示教师复核。
- 编程题边界：当前不执行学生代码，不校验隐藏用例；若 AI 对代码可运行性无法确认，应降低置信度并设置 `needsReview=true`。
