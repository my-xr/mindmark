# 04 业务流程与状态机

> 文档状态：已重建为 UTF-8。更新时间：2026-07-19。  
> 适用范围：MindMark 第一阶段考试系统闭环，包括题库、组卷、考试、答题、批改、成绩、复盘、AI 出题与考试安全审计。

## 1. 考试闭环主流程

```text
基础数据准备
  -> 课程 / 班级 / 学生账号
  -> 题库建设（手工创建 / 批量导入 / AI 生成审核入库）
  -> 试卷组卷
  -> 创建考试与配置时间窗口
  -> 发布考试
  -> 学生登录、首次改密、进入考试
  -> 倒计时、全屏与切屏检测
  -> 草稿保存 / 交卷 / 超时自动交卷
  -> 客观题自动批改
  -> 教师复核主观题
  -> 汇总成绩并发布
  -> 学生查看成绩反馈
  -> 考试复盘分析与 AI 讲评稿 / 导出产物
  -> 归档
```

## 2. 题目生命周期

| 状态 | 说明 | 允许操作 | 下一状态 |
| --- | --- | --- | --- |
| `DRAFT` | 手工草稿或未完成题目 | 编辑、删除、提交审核 | `PENDING_REVIEW` |
| `PENDING_REVIEW` | AI 生成或导入后待审核 | 审核通过、编辑后通过、驳回 | `ACTIVE` / `REJECTED` |
| `ACTIVE` | 可用于组卷 | 加入试卷、禁用 | `DISABLED` |
| `REJECTED` | 审核驳回 | 查看原因、重新生成 | `PENDING_REVIEW` |
| `DISABLED` | 暂不可用 | 启用 | `ACTIVE` |

关键规则：

- 题目必须归属课程，`courseId/courseName` 为后端权威字段。
- 难度采用五级：`VERY_EASY/EASY/MEDIUM/HARD/VERY_HARD`。
- AI 生成题目必须经过人工审核后才能进入正式题库。
- AI 题目内容必须为简体中文；后端在持久化前校验题干、选项、解析与评分点。

## 3. 试卷生命周期

| 状态 | 说明 | 允许操作 | 下一状态 |
| --- | --- | --- | --- |
| `DRAFT` | 试卷草稿 | 编辑基本信息、添加/移除题目 | `READY` |
| `READY` | 已满足组卷约束 | 创建考试、回退编辑 | `DRAFT` |
| `ARCHIVED` | 历史归档 | 查看、复制 | - |

约束：

- 试卷必须绑定课程。
- 加入试卷的题目必须与试卷课程一致且状态为 `ACTIVE`。
- 标记 `READY` 时后端校验题目数量、总分、课程一致性。

## 4. 考试生命周期

| 状态 | 说明 | 允许操作 | 下一状态 |
| --- | --- | --- | --- |
| `DRAFT` | 创建中 | 编辑配置、选择试卷、设置班级与时间 | `PUBLISHED` |
| `PUBLISHED` | 已发布但未开始或正在可进入窗口 | 学生可在窗口内进入考试 | `IN_PROGRESS` / `CLOSED` |
| `IN_PROGRESS` | 有学生正在作答 | 保存草稿、交卷、记录安全事件 | `CLOSED` |
| `CLOSED` | 作答窗口结束 | 自动生成批改任务、汇总成绩 | `GRADING` |
| `GRADING` | 批改中 | 客观题自动批改、教师复核 | `GRADED` |
| `GRADED` | 已完成批改 | 发布成绩 | `PUBLISHED_SCORE` |
| `PUBLISHED_SCORE` | 成绩已发布 | 学生查看反馈、教师复盘 | `ARCHIVED` |
| `ARCHIVED` | 归档 | 只读查看 | - |

时间窗口规则：

- 当前时间早于开始时间：学生列表可见但不可进入。
- 当前时间在开始与结束之间：学生可进入考试。
- 当前时间晚于结束时间：禁止新进入；未交卷答卷进入自动交卷流程。
- 交卷后不可继续编辑答卷。

## 5. 学生答题与交卷状态机

| 状态 | 说明 | 触发条件 |
| --- | --- | --- |
| `NOT_STARTED` | 未开始 | 学生尚未进入考试 |
| `IN_PROGRESS` | 作答中 | 学生进入考试并生成答卷 |
| `DRAFT_SAVED` | 草稿已保存 | 自动保存或手动保存 |
| `SUBMITTED` | 已交卷 | 学生主动交卷 |
| `AUTO_SUBMITTED` | 超时自动交卷 | 到达考试结束时间或剩余时间为 0 |
| `INVALIDATED` | 作答异常作废 | 管理员按规则处理严重作弊事件 |

前端必须具备：

- 考试倒计时。
- 开始考试后强制请求全屏。
- 监听退出全屏、切屏、页面隐藏、失焦等行为。
- 对安全事件进行本地提示并上报后端。
- 超时自动交卷，失败时提示并保留最后一次草稿状态。

## 6. 批改与成绩发布流程

```text
交卷完成
  -> 生成批改任务
  -> 客观题自动批改
  -> 主观题进入教师批改中心
  -> 教师提交分数和评语
  -> 系统汇总总分、得分率、错题与知识点表现
  -> 教师确认发布
  -> 学生查看成绩反馈
```

规则：

- 客观题自动批改必须幂等。
- 主观题批改必须记录批改人、时间、分数与评语。
- 成绩发布后，学生端可见；发布前仅教师端可见。
- 成绩修改需记录审计日志。

## 7. AI 出题审核流程

```text
教师选择课程、题型、五级难度、数量、知识点、Provider
  -> 后端读取教师个人 Provider Key 或全局环境变量
  -> LangGraph 编排生成
  -> 中文与结构校验
  -> 写入待审核题目
  -> 教师审核通过 / 编辑后通过 / 驳回
  -> 通过后进入正式题库
```

Provider 决策：

- 当前 AI 出题主链路仅支持 `OPENAI` 与 `ANTHROPIC`。
- `KIMI` 仅作为历史兼容或讲评稿遗留入口，不再作为出题主链路命名。
- API Key 不允许写入代码、文档、仓库配置或日志。

## 8. 考试安全审计流程

| 事件 | 前端触发 | 后端处理 |
| --- | --- | --- |
| `FULLSCREEN_ENTER` | 成功进入全屏 | 记录事件 |
| `FULLSCREEN_EXIT` | 退出全屏 | 记录风险，累计次数 |
| `VISIBILITY_HIDDEN` | 标签页隐藏 | 记录切屏 |
| `WINDOW_BLUR` | 窗口失焦 | 记录切屏/离焦 |
| `COPY_PASTE` | 复制粘贴 | 记录风险 |
| `AUTO_SUBMIT_TIMEOUT` | 倒计时结束 | 自动交卷并记录原因 |

教师端需要提供考试安全审计视图，按学生、考试、事件类型与风险等级筛选。

## 9. 异常与补偿

- 保存草稿失败：前端提示重试，后端保持最近一次成功草稿。
- 交卷重复提交：后端幂等返回已交卷结果。
- 批改任务重复生成：后端按答卷唯一约束避免重复任务。
- AI Provider 不可用：返回明确错误，不写入半成品题目。
- 导出产物生成失败：任务状态置为失败，可重新发起。
