## 2. 文档驱动开发规则

1. **先文档，后代码**：新增模块、接口、页面、状态流之前，必须先更新对应文档。
2. **变更必留痕**：任何需求范围、流程、权限、数据结构、接口契约变化，都必须更新 `12_需求变更与决策记录.md`。
3. **代码必须可追溯**：重要代码实现应能追溯到需求规格、页面清单、领域模型或 API 设计。
4. **Mock 也按真实接口设计**：阶段 0 可使用 Mock 数据，但类型、字段和状态应尽量贴近未来真实接口。
5. **不做文档外扩张**：当前 MVP 聚焦考试闭环，考试闭环外模块不得在未更新路线图前自行扩展。

## 3. 文档变更入口

- 普通需求补充：更新 `02_需求规格说明书.md` 与相关专题文档。
- 页面或交互变化：更新 `05_信息架构与页面清单.md`、`06_前端开发规范.md`。
- 数据或接口变化：更新 `07_领域模型与数据字典.md`、`08_API设计规范.md`，进入后端准备阶段时同步更新 `19_后端接口契约准备.md`。
- 权限或安全变化：更新 `09_权限与安全设计.md`。
- AI 能力变化：更新 `10_AI能力与人工审核规范.md`。
- 重大取舍：追加 `12_需求变更与决策记录.md` 的 ADR 记录。
- 迭代复盘：每次开发完成后按 `14_迭代计划与复盘.md` 输出本轮结果、风险和下一步计划。
- 工程边界：MindMark 根目录是完整项目根目录，前端业务代码必须放在 `apps/mindmark-web`，后端代码放在 `apps/mindmark-server`。
