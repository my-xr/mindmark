# 03 MVP 范围与版本路线图

## 1. 路线图原则

1. 先形成考试闭环，再扩展作业、练习、课程和复杂画像。
2. 先前端原型和交互质量，再后端持久化和真实接口。
3. AI 能力先以可审核工作流落地，再逐步增强准确率、RAG 和工具链。
4. 每个阶段都要有可验收产物，避免“大而全但不可用”。

## 2. 阶段划分

| 阶段 | 名称 | 目标 | 主要产物 |
| --- | --- | --- | --- |
| Phase 0 | 文档与前端原型 | 建立文档体系，完成考试闭环核心页面 Mock 原型 | 文档中心、页面清单、Mock 数据、前端路由和核心页面 |
| Phase 1 | 前端闭环增强 | 教师端与学生端核心流程体验完整 | 题库、AI 出题审核、组卷、答题、批改复核、成绩、复盘页面 |
| Phase 2 | 后端基础闭环 | Spring Boot 单体、PostgreSQL、Redis 接入，替换核心 Mock | 鉴权、RBAC、题库、考试、答卷、批改、成绩接口 |
| Phase 3 | AI 能力接入 | 接入可替换大模型 Provider，落地 AI 出题和 AI 预批改 | Provider 抽象、调用审计、人工审核、提示词模板 |
| Phase 4 | 复盘与画像增强 | 完善知识点诊断、错因归纳和基础学生画像 | 画像数据、复盘指标、学生建议、讲评稿 |

## 3. Phase 0 范围

### 3.1 必做

- 文档体系建设。
- 明确完整项目采用 monorepo 结构，前端、后端、AI 辅助服务均在子项目中创建。
- 信息架构与页面清单。
- 前端工程结构约定，创建 `apps/mindmark-web`，不在根目录直接写业务 `src`。
- Mock 数据与类型定义约定。
- 教师端核心页面原型：工作台、题库、AI 出题、组卷、考试管理、批改、成绩、复盘。
- 学生端核心页面原型：考试列表、考试须知、答题、成绩反馈。

### 3.2 不做

- 真实后端接口。
- 真实数据库和 Redis。
- 真实大模型 API 调用。
- 代码沙箱和 L3 防作弊。

## 4. 后续阶段边界

- Phase 1：完善前端交互状态、表单校验、统一 API service、统一加载/错误/空状态/权限态组件。
- Phase 2：实现 Spring Boot 模块化单体、PostgreSQL、Redis、鉴权、RBAC、审计日志、核心业务接口。
- Phase 3：实现大模型 Provider / Adapter、API Key 安全、AI 出题、AI 预批改、调用审计。
- Phase 4：增强复盘指标、错因归纳、知识点诊断、基础学生画像。

## 6. MVP 收敛期（三轮内完成考试闭环真实验收）

> 更新时间：2026-07-18。Iteration 17 后进入阶段性检查，不立即扩散新功能，先用三轮收敛计划完成考试闭环所有端的真实化和验收。

| 收敛轮次 | 主题 | 必达目标 | 对应文档 |
| --- | --- | --- | --- |
| Round 1 | 基础数据与权限边界收敛 | 课程/班级实体化；教师/助教授权对接真实班级；学生考试和答卷从登录态识别；考试参与者来自真实学生名单。 | `21_考试闭环缺口分析与三轮收敛计划.md` |
| Round 2 | 考试答题、批改与成绩发布硬化 | 考试状态机、自动保存、超时交卷、交卷幂等、批改一致性、成绩发布/撤回策略可验收。 | `21_考试闭环缺口分析与三轮收敛计划.md` |
| Round 3 | 复盘 AI、导出与端到端验收收口 | 复盘分析和 AI 讲评稿后端真实落地；成绩/报告导出接入 MinIO；完整登录态 E2E Smoke 通过。 | `21_考试闭环缺口分析与三轮收敛计划.md` |

三轮收敛期内原则上不新增考试闭环以外的大功能；移动端 App、高等级防作弊、多租户和长期画像等能力后置。
