## 1. Decision principles

- Documentation first: clarify requirement, domain model, API, UI, and acceptance criteria before coding.
- This repository is the full project root. Frontend and backend live in apps/mindmark-web and apps/mindmark-server.
- Phase 1 target is the exam closed loop: question bank -> paper assembly -> exam creation -> student answering -> auto/AI grading -> score publish -> review analysis.
- Authentication uses Sa-Token, not Spring Security.
- Do not commit real API keys in code, docs, or logs. Teacher-owned AI keys must be stored encrypted.

## 3. AI Provider decisions

- Main AI generation flow uses OpenAI/Anthropic-compatible provider abstraction.
- Kimi can be used by configuring OpenAI-compatible baseUrl and the target model name.
- LangGraph orchestrates question generation.
- Teacher personal API key has priority over global environment variables.
- Prompts must require Simplified Chinese, strict JSON, and no Markdown wrapper.
- Provider configuration belongs in teacher personal settings, not the dashboard.

## 3.1 Login portal decisions

- Administrator, teacher/TA, and student use separate login pages:
  - `/auth/entry/8b7f2d4c91e6a3f0c5d8b1e7`
  - `/auth/entry/3e9a6c1f74b8d205a7c4f0e2`
  - `/auth/entry/6d2c8a5f1b9e4d70c3a6f8e1`
- All three pages call the same backend authentication contract; the frontend additionally verifies that the returned role matches the selected portal.
- A role mismatch clears the session and displays a Chinese actionable error. It must not redirect a student into the teacher portal or an administrator into the student portal.
- Login pages do not display cross-portal switching links. Portal URLs are distributed separately by deployment or organization administrators.
- Portal URLs do not contain role words such as `admin`, `teacher`, or `student`; each portal uses a distinct opaque entry code.
- Login forms do not prefill development usernames or passwords, preventing credentials from being exposed in the browser.
- `/auth/login` remains as a compatibility entry: it defaults to the teacher entry code, but follows the target portal when a safe `redirect` points to the admin or student portal.
- Unauthenticated access to `/admin/*`, `/teacher/*`, and `/student/*` redirects to the corresponding login page with the original path preserved in `redirect`.

## 4. Exam account decisions

- Student accounts are created from roster import.
- Default password is the last 6 digits of student number.
- First login requires password change.
- Teacher, TA, and admin can reset student passwords.
- Duplicate roster import must not create duplicate accounts.

## 5. Exam security decisions

- Student exam page must show countdown.
- Starting an exam requests browser fullscreen.
- Fullscreen exit, tab switch, blur, copy, and paste are reported as security events.
- Timeout submission must be idempotent and backed by server-side safeguards.
- Teacher side needs security audit visualization.

## 6. UI and engineering decisions

- Default theme is Light.
- Keep the UI modern, concise, aligned, and avoid decorative effects that block text.
- Use unified font size, button size, table density, pagination, and card spacing.
- Button text expanded/collapsed and bold style are controlled from personal settings.
- Large lists must use enterprise-grade pagination and stable empty-page correction.

## 7. Markdown question import decision - 2026-07-22

Background: the user already has Markdown exam questions. The sample file is in the exam directory and must be imported into the system question bank.

Decision:

- Teacher question bank page provides an Import MD action.
- Backend provides POST /api/v1/questions/import/markdown.
- Request body contains courseId, fileName, and markdown.
- Frontend reads .md as UTF-8 text and submits JSON.
- Knowledge points are written as the selected course name, not the internal K labels from Markdown.
- Parser supports question heading, options, answer, reference answer points, analysis, and scoring criteria.
- Type detection prioritizes question number/type text and falls back to section heading.
- Five-level difficulty maps from star count; missing difficulty defaults to MEDIUM.
- Score is read from question heading first, section default second, and system default last.
- Duplicate rule is courseId + title + type; duplicate questions are skipped.
- question.title is upgraded to TEXT to avoid long-stem import failures.

Validation:

- Real Markdown sample parses 78 questions.
- First import result: parsedCount=78, importedCount=78, skippedCount=0.
- Second import result: parsedCount=78, importedCount=0, skippedCount=78.
- Backend compile, Markdown parser tests, frontend typecheck, and frontend build passed.

## 2026-09-30：选择题答卷级随机化与教师参考答案

- 需求：学生参加同一套试卷时，单选题、多选题的选项应随机展示；同一学生刷新后顺序必须稳定。教师需可查看每套试卷完整参考答案。
- 决策：
  - 不修改题库标准选项，也不在前端临时打乱后直接提交。
  - 在 `answer_sheet.option_order_json` 保存“展示选项键 -> 题库标准选项键”的答卷级映射。
  - 学生仅通过 `GET /api/v1/student/exams/{examId}/paper` 获取答卷专属试卷；通用 `/api/v1/papers/{paperId}` 与 `/questions` 改为教职工接口。
  - 判分服务在比较单选/多选答案前先执行映射还原，保证随机展示不改变标准答案含义。
  - 新增 `GET /api/v1/papers/{paperId}/answer-key`，仅管理员、教师、助教可读取完整参考答案。
  - 试卷被用于创建考试后自动发布并冻结；其引用题目不可再编辑，防止历史考试、参考答案和判分依据漂移。
- 历史兼容：已有作答记录而缺少映射的答卷按题库原始顺序补齐，避免历史提交被重新解释。
- 验收：
  - 后端编译、单元测试通过；
  - 前端 lint、类型检查、生产构建通过；
  - 本地 `mindmark` 数据库 Flyway 已成功升级至 `V30__answer_sheet_option_order.sql`。
- 运行态限制：本次本机检查时 PostgreSQL 正常，但 Redis `6379` 未监听；登录限流按 fail-closed 策略返回“登录安全服务暂不可用”，因此真实登录 Smoke 需在 Redis 恢复后重新执行，不以当前结果声明端到端通过。
