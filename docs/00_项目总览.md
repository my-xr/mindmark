# 00 项目总览

## 1. 项目基本信息

| 项目项 | 内容 |
| --- | --- |
| 项目名称 | MindMark |
| 中文名 | 明镜台 |
| 名称寓意 | 身是菩提树，心如明镜台。帮助教师与学生看清学习过程、考试结果与知识掌握状态。 |
| 项目定位 | 面向院校 / 教师内部使用的智慧教考评一体化平台 |
| 当前阶段 | 阶段 0：优先完成前端原型、信息架构和考试闭环核心页面 |
| 当前核心目标 | 打通“出题 → 组卷 → 开考 → 批改 → 出分 → 复盘”的考试系统闭环 |
| 原始需求来源 | `docs/需求描述.md` |
| 开发协作准则 | `docs/MindMark-开发提示词.md` |

## 2. 长期产品愿景

MindMark 长期覆盖以下教学链路：

```text
教（课堂教学） → 学（课后学习） → 练（课后练习） → 作（课后作业） → 考（平时考试、期末考试） → 画（学生画像、查漏补缺）
```

当前不追求一次性完成全量平台，而是以考试系统闭环为 MVP，逐步沉淀题库、考试、成绩和画像数据，为后续教学、练习、作业与个性化学习扩展预留基础。

## 3. 当前阶段边界

### 3.1 当前优先级

1. 建立完整文档体系，保证后续代码开发有据可依。
2. 完成前端信息架构、页面原型和核心流程设计。
3. 使用 Mock 数据打通教师端与学生端核心体验。
4. 页面结构、类型定义、Mock 数据和 API service 为后续真实接口替换预留空间。
5. 前端达到企业级项目的可维护标准后，再进入后端与数据库实现。

### 3.2 MVP 闭环

```text
题库管理 → AI 出题 / 人工录题 / 批量导入 → 教师审核入库 → 组卷 → 发布考试 → 学生答题 → 自动批改 / AI 预批改 / 教师复核 → 成绩发布 → 考试复盘 / 基础学生画像
```

## 4. 核心设计原则

| 原则 | 说明 |
| --- | --- |
| 统一工作台 | 教师尽量在一个系统内完成题库、组卷、考试、批改、成绩发布和复盘。 |
| AI 优先，人审兜底 | 出题、批改、试卷讲评、错因归纳由 AI 先处理，再由教师 / TA 审核。 |
| 数据贯通 | 题目、试卷、考试、作答、成绩、知识点诊断最终沉淀到学生画像。 |
| 企业级项目 | 考虑权限、审计、异常处理、数据一致性、可维护性、可扩展性和可测试性。 |
| 渐进交付 | 先建立清晰架构和闭环体验，再逐步增加后端、缓存、AI/RAG 和高级能力。 |

## 5. 技术约束总览

| 层级 | 约束 |
| --- | --- |
| 前端 | Vue 3 + TypeScript + 成熟 UI 库；阶段 0 以 Mock 数据为主。 |
| 后端 | Spring Boot 模块化单体优先，后续视复杂度拆分。 |
| AI 辅助服务 | 智能体、RAG、文档解析等 Spring Boot 成本较高能力可引入 Python FastAPI。 |
| 数据库 | PostgreSQL；后续可扩展向量检索能力。 |
| 缓存 | Redis；支撑约 300 人在线考试的临时状态、草稿、倒计时、限流和热点缓存。 |
| 大模型接入 | API Key 方式；Provider / Adapter 抽象；禁止硬编码真实 Key。 |
| 安全 | 鉴权、权限控制、审计日志、异常处理、参数校验、脱敏和加密存储。 |

## 6. 明确非目标

当前阶段不实现以下能力，除非需求文档明确变更：代码沙箱、MOOC 公开课、教务系统深度对接、论文/代码查重、实时音视频直播、同伴互评、代码 Review 类作业、考试闭环外复杂模块、防作弊 L3 严格能力。

## 7. 代码开发前置检查

开发任何功能前必须回答：

1. 该功能属于哪个 MVP 闭环节点？
2. 是否已经出现在 `02_需求规格说明书.md`？
3. 是否涉及页面、数据模型、接口、权限、安全或 AI？如涉及，是否更新对应文档？
4. 是否改变已有约定？如改变，是否更新 `12_需求变更与决策记录.md`？
