# Codex 项目轻量上下文

> 用途：用于后续新会话或省 token 模式快速恢复 MindMark 项目上下文。本文只记录稳定约束与当前阶段，不替代正式需求、API、领域模型和流程文档。

## 1. 项目定位

MindMark 是面向教学与考试场景的 AI 辅助考试闭环系统，第一阶段目标是完成“教师出题/组卷/开考/批改/出分/复盘 + 学生考试/查看成绩”的完整闭环。

## 2. 仓库与应用结构

- 当前仓库是完整项目根目录，不在根目录直接编写业务 `src`。
- 前端应用：`apps/mindmark-web`
- 后端应用：`apps/mindmark-server`
- 文档目录：`docs`
- 重要契约：`apps/mindmark-server/openapi/mindmark-api.yaml`

## 3. 核心技术约束

### 前端

- Vue 3 + TypeScript + Vite。
- 页面风格：现代简洁、默认 Light、少装饰、对齐清爽、字体克制。
- 筛选区域默认展示一行，支持展开；避免模块过多导致页面混乱。
- 优先组件化复用，不在页面中堆叠重复样式和重复逻辑。

### 后端

- Spring Boot。
- 鉴权使用 Sa-Token，不使用 Spring Security。
- 数据库使用 PostgreSQL，开发库名为 `mindmark`，不要使用 `postgres` 数据库。
- ORM + 数据库连接池。
- Redis：`6379`，无密码。
- MinIO：`9000/9001`，bucket 为 `mindmark-artifacts`。

## 4. 账号与考试安全要求

- 支持教师、助教、学生等角色。
- 支持导入学生名单创建账号。
- 学生默认密码为学号后 6 位。
- 学生首次登录必须修改密码。
- 教师/助教可帮助学生重置密码。
- 考试需要倒计时。
- 考试需要强制全屏。
- 需要记录切屏、离开全屏等考试安全事件。
- 超时自动交卷是考试闭环 P0 能力。

## 5. AI Provider 约束

- AI 出题主链路不绑定 Kimi。
- AI 出题 Provider 优先支持：
  - OpenAI-compatible Provider
  - Anthropic-compatible Provider
- 不同教师可以配置自己的 Provider 服务器地址、模型与 API Key。
- API Key 不得写入代码、文档、日志或接口响应。
- Kimi Key 仅作为本地环境变量或历史兼容使用，不作为 AI 出题主链路硬编码依赖。
- AI 生成题目必须输出中文，并进入人工审核后再入正式题库。

## 6. 文档驱动规则

- 需求变更必须更新过程文档，但采用“差量更新”，避免全量重写。
- 只更新受影响文档：
  - 业务流程/状态变化：`04_业务流程与状态机.md`
  - 领域对象/字段/枚举变化：`07_领域模型与数据字典.md`
  - API 变化：`08_API设计规范.md` 与 OpenAPI
  - 测试/验收变化：`11_测试验收与质量门禁.md`
  - 决策变化：`12_需求变更与决策记录.md`
  - 迭代计划/剩余缺口：`14_迭代计划与复盘.md` 或 `21_考试闭环缺口分析与三轮收敛计划.md`
  - 前端规范变化：`06_前端开发规范.md` / `18_页面级UI设计规范.md`

## 7. 省 token 开发规则

后续默认采用省 token 高质量模式：

1. 每轮只读取最少必要文件。
2. 只修改与本轮目标直接相关的代码。
3. 文档只做必要章节的差量更新。
4. 避免全量扫描、全量重写、重复总结历史。
5. 命令输出只保留关键错误和验证结论。
6. 每轮优先跑必要测试，不默认跑所有测试。
7. 最终回复使用简短格式：完成内容、验证结果、修改文件、下一步建议。
8. 每 3-5 轮再做一次集中复盘和文档收敛。
