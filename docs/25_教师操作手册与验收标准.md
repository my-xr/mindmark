# 25 教师操作手册与验收标准

> 版本：v1.0  
> 编写日期：2026-09-18  
> 适用范围：MindMark 教师端真实接口验收、考试闭环手工验收、上线前业务验收  
> 重要说明：本手册用于真实业务验收。仅使用 Mock 数据完成的操作，只能证明页面演示可用，不能判定系统验收合格。

---

## 1. 手册目标

本手册将教师从登录系统开始，完整走通以下闭环：

```text
登录
  → 个人配置 / AI Provider 连接测试
  → 学生名单导入与账号治理
  → 题库筛选、导入、编辑与删除
  → AI 出题、异步任务、人工审核
  → 试卷创建、随机组卷 / 智能组卷
  → 考试创建与参考班级配置
  → 学生提交答卷
  → 批改、客观题判分、AI 主观题评分、教师复核
  → 成绩发布
  → 复盘分析、安全审计、AI 讲评稿和导出
```

每一步都包含：

- 操作步骤；
- 预期结果；
- 合格标准；
- 失败时应记录的信息。

## 2. 验收结论规则

### 2.1 验收状态

| 状态     | 含义                                                         |
| -------- | ------------------------------------------------------------ |
| `未执行` | 尚未操作                                                     |
| `通过`   | 实际结果与预期一致，且满足本手册的合格标准                   |
| `失败`   | 功能可以操作，但结果错误、数据错误、状态错误或体验不满足要求 |
| `阻塞`   | 因服务未启动、账号无权限、基础数据缺失等原因无法继续         |
| `不适用` | 当前测试场景明确不需要该能力，必须填写原因                   |

### 2.2 通过门槛

考试闭环只有同时满足以下条件，才能判定为“教师端验收合格”：

1. 所有 P0 步骤通过；
2. 登录、权限、数据保存、考试创建、答卷批改、成绩发布均使用真实后端接口；
3. 刷新浏览器或重新登录后，已保存数据仍然存在；
4. 题库、试卷、考试、学生名单、答卷和成绩数量一致；
5. 分页切换、筛选、返回、刷新不会出现重复、空页、错页或数据串联；
6. 不出现前端运行时错误、接口 5xx、`MM-500-001`、乱码或英文 AI 题目；
7. AI 结果必须经过教师审核后才能进入正式题库；
8. 未授权教师不能看到其他教师或其他课程、班级的数据；
9. 失败场景有明确、可关闭、可理解的中文提示；
10. 所有阻塞项必须有处理结论，不能以“暂时跳过”代替验收。

### 2.3 缺陷等级

| 等级 | 判定                               | 示例                                              |
| ---- | ---------------------------------- | ------------------------------------------------- |
| P0   | 阻断闭环，必须修复                 | 无法登录、无法创建考试、无法交卷、成绩无法发布    |
| P1   | 核心功能异常或数据风险，验收不通过 | AI 题目未落库、批改分数错误、权限越界、分页漏数据 |
| P2   | 体验或视觉问题，不阻断业务         | 间距不一致、按钮文字不清晰、提示不够友好          |
| P3   | 优化建议                           | 非核心快捷操作、次要文案优化                      |

## 3. 验收前准备

### 3.1 基础环境

真实验收必须确认以下服务已启动：

| 服务          | 地址 / 配置             | 合格状态                                         |
| ------------- | ----------------------- | ------------------------------------------------ |
| 前端          | `http://localhost:5173` | 页面可以打开                                     |
| 后端          | `http://localhost:8080` | 健康检查返回 `UP`                                |
| PostgreSQL    | `localhost:5432`        | 使用 `mindmark` 数据库，不使用 `postgres` 数据库 |
| Redis         | `localhost:6379`        | 可连接                                           |
| MinIO API     | `localhost:9000`        | 可连接                                           |
| MinIO Console | `localhost:9001`        | 可登录                                           |
| MinIO Bucket  | `mindmark-artifacts`    | 已创建                                           |

PowerShell 检查命令：

```powershell
Test-NetConnection 127.0.0.1 -Port 5173
Test-NetConnection 127.0.0.1 -Port 8080
Test-NetConnection 127.0.0.1 -Port 5432
Test-NetConnection 127.0.0.1 -Port 6379
Test-NetConnection 127.0.0.1 -Port 9000
```

后端健康检查：

```powershell
Invoke-WebRequest http://localhost:8080/api/v1/system/health
```

预期结果：

- HTTP 状态码为 `200`；
- 响应中的业务状态为成功；
- `data.status` 为 `UP`；
- `data.service` 为 `mindmark-server`。

### 3.2 前端必须使用真实接口

打开 `apps/mindmark-web/.env`，确认：

```dotenv
VITE_USE_MOCK=false
VITE_API_BASE_URL=/api
```

验收期间浏览器开发者工具的 Network 面板中，应看到类似以下请求：

```text
/api/v1/auth/login
/api/v1/auth/me
/api/v1/teacher/dashboard
/api/v1/questions
/api/v1/papers
/api/v1/exams
/api/v1/grading-tasks
/api/v1/score-summaries
/api/v1/exams/reviews
```

如果请求只发生在浏览器内存、没有 `/api/v1` 请求，或页面显示的是固定 Mock 数据，本次只能记录为“Mock 验证”，不能判定真实接口合格。

## 4. 教师端导航和权限边界

登录教师账号后，左侧导航应包含：

1. 教师工作台；
2. 题库管理；
3. AI 出题审核；
4. 试卷与组卷；
5. 考试管理；
6. 学生名单与账号；
7. 批改中心；
8. 成绩中心；
9. 复盘分析；
10. 个人配置。

权限边界：

- 教师：可以使用完整的题库、组卷、考试、成绩和复盘能力；
- 助教：可以使用被授权的题库、学生名单、考试和批改能力；无权访问教师专属页面时，应明确显示 403；
- 学生：不能进入教师页面；
- 管理员：负责课程、班级、角色和账号治理，不代替教师完成考试业务。

权限验收合格标准：

- 直接输入无权限页面地址，不能通过前端隐藏绕过权限；
- 后端返回 401 / 403 时，前端显示明确提示或跳转到对应错误页；
- 教师只能看到自己有权限的课程、班级、题库和考试；
- 退出登录后，浏览器刷新不能继续访问受保护页面。

## 6. T-01 登录、会话和首次改密

### 操作步骤

1. 使用教师账号打开 `/auth/login`；
2. 输入教师账号和密码，点击“登录”；
3. 确认进入“教师工作台”；
4. 刷新浏览器；
5. 退出登录；
6. 返回浏览器历史页面或直接输入教师页面地址；
7. 使用助教账号重复一次，检查助教权限；
8. 如使用首次登录账号，按页面要求修改密码后重新登录。

### 预期结果

- 登录成功后进入教师工作台；
- 刷新后仍保持登录；
- 退出后访问教师页面会回到登录页或显示未授权；
- 首次改密成功后，旧密码不可登录，新密码可以登录；
- 密码不出现在 URL、页面明文提示或 Network 请求日志中；
- 错误密码有中文错误提示，提示可以关闭或在下一次操作后自动更新。

### 合格标准

- 登录、刷新、退出、重新登录全部成功；
- 当前用户姓名、角色和菜单正确；
- 不出现 `/error/403` 误跳转；
- 不出现 `MM-500-001`、`Student profile not found` 等与教师登录不相关的错误；
- 后端真实返回用户信息，不使用固定教师名称。

## 7. T-02 教师工作台真实数据

### 操作步骤

1. 进入“教师工作台”；
2. 记录统计卡片中的题目、考试、待批改和待复盘数据；
3. 查看“近期待办”；
4. 点击“查看考试”或待办项；
5. 返回工作台；
6. 点击“刷新数据”；
7. 在浏览器 Network 中确认刷新请求指向教师工作台接口。

### 预期结果

- 统计卡片来自当前教师账号的真实数据；
- 近期待办与考试、批改、复盘页面的数据一致；
- 点击待办可以进入正确页面；
- 刷新后数据重新从后端读取，而不是只刷新前端内存；
- 加载中、空数据、接口失败分别显示对应状态。

### 合格标准

- 页面无固定 Mock 名称、虚构数量或过期测试数据；
- 刷新前后数据与数据库一致；
- 统计数字不出现负数、`NaN`、`undefined`；
- 页面无横向溢出，按钮和表格不遮挡文字；
- 后端接口失败时能看到可理解的错误提示和重试入口。

## 8. T-03 个人配置和 AI Provider 连接测试

### 8.1 界面偏好

1. 进入“个人配置”；
2. 检查“按钮文字”开关；
3. 切换展开 / 收起；
4. 返回教师工作台、题库管理、组卷、考试管理等页面；
5. 检查所有通用按钮是否同步变化；
6. 检查“按钮字重”开关；
7. 刷新浏览器，再次确认设置仍然生效。

合格标准：

- 默认按钮为展开状态；
- 收起后保留图标，悬浮可以看到完整文字；
- 展开后文字能够稳定恢复，不抖动、不被裁剪；
- 所有页面按钮尺寸和字重一致；
- 设置刷新后仍然保留。

### 8.2 Provider 配置

当前 Provider 入口在“个人配置”，AI 出题页面只选择 Provider，不维护服务器地址和 API Key。

1. 进入“个人配置”；
2. 选择 `OpenAI Compatible`；
3. 填写：
   - 服务器地址；
   - 模型名称；
   - API Key；
4. 先点击“测试连接”；
5. 确认测试成功后点击“保存配置”；
6. 刷新页面，检查配置状态；
7. 切换到 `Anthropic`，确认不同 Provider 配置互不覆盖；
8. 如使用 Kimi，使用 OpenAI Compatible 方式配置，不要把 Kimi 固定写死为系统唯一 Provider。

### 预期结果

- 服务器地址和模型名称可以单独配置；
- 测试失败时显示 HTTP 状态、模型或服务错误的中文说明；
- 测试成功后显示成功状态、耗时、服务器地址和模型；
- API Key 保存后只显示脱敏预览，输入框不会回显完整 Key；
- 留空 API Key 保存时，系统沿用已保存的 Key；
- 重新打开页面后，Key 字段仍为空或脱敏，不显示完整密钥。

### 合格标准

- 测试连接和保存配置都是真实后端接口；
- Provider、Base URL、模型三者被正确保存；
- 不能因为保存配置把模型自动替换成默认模型；
- AI Key 不写入前端源码、`.env`、日志和页面 HTML；
- 数据库中 Key 必须以服务端加密形式保存，验收报告不得记录完整 Key；
- 不出现英文错误堆栈、`invalid temperature` 未翻译信息或空响应未说明。

## 9. T-04 学生名单导入和账号治理

### 操作步骤

1. 进入“学生名单与账号”；
2. 选择目标教学班；
3. 点击“下载模板”；
4. 打开模板，确认字段顺序：

```text
studentNo,name,email,className,grade,major
```

5. 准备至少 10 名学生数据；
6. 将 CSV 内容粘贴到“CSV 学生名单”区域；
7. 点击“导入并创建账号”；
8. 记录新增、跳过重复、失败数量；
9. 使用相同 CSV 再导入一次；
10. 翻页查看“已导入学生”；
11. 选择一名学生点击“重置密码”；
12. 使用该学生账号登录，确认初始密码为学号后 6 位；
13. 确认首次登录被要求修改密码；
14. 修改密码后重新登录学生端。

### 预期结果

- 第一次导入新增学生账号；
- 第二次导入相同学号被跳过，不创建重复账号；
- 失败行展示行号、学号和失败原因；
- 学生列表支持分页；
- 教师或助教可以重置学生密码；
- 重置后的初始密码为学号后 6 位；
- 学生首次登录必须修改密码；
- 修改密码成功后可以进入学生端，不跳转错误 403。

### 合格标准

- 数据库中同一学号只有一个有效账号；
- 学生账号、学生档案、班级关系正确关联；
- 账号密码不能以明文出现在页面、接口响应或日志；
- 导入结果数量满足：`新增 + 跳过 + 失败 = 输入有效行数`；
- 切换班级会重置分页并加载对应班级数据；
- 分页最后一页删除或变更后不会出现空页；
- 无授权教师无法导入或查看其他班级学生。

## 10. T-05 题库管理

### 10.1 筛选和分页

1. 进入“题库管理”；
2. 选择课程；
3. 依次按关键词、题型、难度、状态、来源筛选；
4. 检查课程筛选是否只显示当前课程题目；
5. 点击分页下一页、上一页、页码和每页条数；
6. 收起筛选，再展开筛选；
7. 点击表格行查看题目详情；
8. 检查题干、课程、知识点、题型、难度、来源、状态、更新时间和操作列；
9. 点击更新时间排序；
10. 在长题干上悬浮查看完整内容。

### 合格标准

- 题库使用真实分页接口；
- 当前页数量、总数量、分页页码与接口响应一致；
- 筛选条件变化后页码自动回到第一页；
- 切换每页条数后数据不重复、不漏数据；
- 长题干省略显示，悬浮可查看完整内容；
- 课程名和知识点为独立列，不混入题干；
- 操作列固定，不因横向滚动消失；
- 表格无文字遮挡、蓝色背景覆盖文字或横向布局崩坏。

### 10.2 新增和编辑题目

1. 点击“新增题目”；
2. 选择课程、题型、五级难度和分值；
3. 输入题干、知识点、参考答案和解析；
4. 客观题配置选项；
5. 主观题配置评分点、分值、关键词和是否必需；
6. 保存题目；
7. 在列表中打开刚创建的题目；
8. 点击“编辑题目”；
9. 修改一个字段后保存；
10. 刷新页面验证修改仍存在；
11. 点击“删除”，确认二次确认；
12. 刷新并搜索，验证题目不再出现。

### 合格标准

- 编辑在题目详情抽屉中完成，不在列表下方展开临时表单；
- 题型、难度、课程和分值保存正确；
- Markdown 导入题目查看时显示结构化内容，不直接显示原始 Markdown；
- 删除有二次确认；
- 删除成功后列表、分页总数和可选题目池同步更新；
- 已被试卷或考试引用的题目，系统必须给出明确限制或风险提示，不允许静默破坏历史数据；
- 保存失败时保留用户输入，不丢失编辑内容。

### 10.3 Markdown 题库导入

1. 点击“导入 MD”；
2. 选择归属课程；
3. 选择 `exam/题库.md` 或同格式文件；
4. 确认系统识别单选、多选、判断、填空、简答、程序 / 编程题；
5. 点击“开始导入”；
6. 记录解析、入库、跳过数量和警告；
7. 搜索导入题目；
8. 打开题目详情，确认不是原始 Markdown 字符串堆叠。

合格标准：

- 导入题目的课程归属正确；
- 知识点按照当前课程建立；
- 重复题自动跳过；
- 解析失败的题目有明确警告；
- 导入成功后可编辑、可组卷、可删除；
- 题干、选项、答案、解析在详情页结构化展示。

## 11. T-06 AI 出题审核闭环

### 11.1 生成任务

1. 进入“AI 出题审核”；
2. 确认课程为下拉选择，不是手动录入；
3. 选择 Provider；
4. 填写知识点；
5. 选择题型；
6. 选择五级难度；
7. 设置数量为 `1`，生成一次；
8. 再设置数量为 `3` 或 `5`，生成一次；
9. 点击“生成题目”；
10. 查看异步任务卡片和“AI 出题任务历史”。

### 预期结果

- 点击后先创建生成任务，不阻塞页面等待长请求；
- 任务状态至少能区分进行中、成功、失败；
- 多题任务的已生成数量会从 `0 / N` 变化到完成数量；
- 生成完成后题目进入“待审核题目”；
- 失败任务显示失败原因，可以重新发起；
- 生成中的按钮有 loading 状态，不能重复提交同一个任务。

### 11.2 审核、编辑和入库

1. 在“待审核题目”查看题干、选项、答案、解析、知识点和 AI 元信息；
2. 检查题目是否为中文；
3. 点击“编辑题目”，跳转题库管理详情；
4. 修正题干、选项、答案、解析或评分点；
5. 保存；
6. 返回 AI 审核页；
7. 点击“通过”；
8. 在题库管理中按来源、课程或关键词搜索；
9. 再选择一题点击“驳回”；
10. 在 AI 审核页切换到“已驳回”；
11. 点击“编辑驳回题”，修正后再次保存；
12. 确认题目重新进入待审核状态。

### 合格标准

- AI 题目未经教师审核不能进入正式题库；
- 通过审核后题目在题库中可查询、可编辑、可组卷；
- 驳回题可以二次编辑；
- 二次编辑后必须重新审核，不能绕过审核直接发布；
- 生成数量为 3 或 5 时，任务历史和待审核数量一致；
- 生成结果不能全部为空、英文、重复或缺少正确答案；
- 任何 Provider 错误均显示可理解的中文错误，不暴露 Key；
- 审核动作可追溯到教师、时间、题目和任务。

## 12. T-07 试卷与组卷

### 12.1 创建试卷

1. 进入“试卷与组卷”；
2. 点击“新增试卷”；
3. 选择课程；
4. 输入试卷名称、说明和考试时长；
5. 保存；
6. 确认试卷以整行列表显示；
7. 点击试卷行进入试卷编辑页。

合格标准：

- 试卷列表占整行，点击行可以进入编辑页；
- 新试卷默认是草稿状态；
- 课程、名称、时长和说明保存后刷新仍存在；
- 试卷删除有确认，并且不能静默删除已用于考试的历史试卷；
- 状态为草稿、可用于考试、已归档时，操作按钮和限制清晰。

### 12.2 手动加入和移除题目

1. 在试卷编辑页确认“可选题目”只来自当前课程；
2. 使用题型、难度、知识点、关键词筛选；
3. 点击“加入试卷”；
4. 检查当前试卷题目分页；
5. 点击“移除题目”；
6. 切换试卷；
7. 再切回原试卷；
8. 检查分页是否自动重置和数据是否一致。

合格标准：

- 可选题目不会混入其他课程；
- 当前试卷题目和可选题目都有独立分页；
- 加题 / 移除题后总数、总分和分页自动校正；
- 删除最后一条导致的空页会回到上一页；
- 题干过长时省略显示，不能撑宽整行；
- 加入已存在题目时有明确提示，不产生重复题。

### 12.3 随机组卷

1. 点击“100 分模板”；
2. 检查题型、数量、分值、难度范围；
3. 确认预计总分为 `100 / 100`；
4. 点击“质量预览”；
5. 查看题型、难度和知识点分布；
6. 点击“随机组卷”；
7. 确认写入方式；
8. 刷新试卷并核对题目。

合格标准：

- 分值不等于目标总分时，组卷按钮必须禁用；
- 库存不足时显示缺口，不允许伪造完成；
- 随机组卷不会重复选择同一道题；
- 实际题型、难度、知识点分布与规则一致；
- 组卷结果保存后刷新仍存在。

### 12.4 智能组卷

1. 配置目标总分；
2. 为不同题型指定难度和知识点；
3. 点击“质量预览”；
4. 检查智能体计划、选择理由、风险和建议；
5. 点击“智能组卷”；
6. 查看最终质量报告；
7. 人工抽查题型、难度和知识点是否满足预期。

合格标准：

- 智能组卷只能调用当前课程题库；
- 智能体输出的是可解释的组卷计划，不是无依据的随机结果；
- 题库库存不足时明确报告缺口；
- 最终写入题目必须能追溯到题库题目 ID；
- 不因智能组卷改变题目原始答案或解析。

1. 在答卷详情点击“规则判分”；
2. 检查客观题系统分；

- 教师可以修改系统默认分；
- 不及格答卷有独立的复核入口；
- 未复核答卷不能进入“已完成批改”；
- 提交复核后任务状态、复核时间和复核人正确；
- 题目分页在 30～50 道时可正常切换，切换答卷会重置题目分页。

5. 点击“复核不及格”；

合格标准：

- 批量操作有 loading、完成数量和失败提示；
- 批量操作不会重复创建评分任务；
- 不及格答卷不会被普通“一键核对”静默跳过；
- 失败项可以定位到学生和考试。

## 18. T-13 异常和安全专项验收

### 必测异常

| 场景        | 操作                     | 合格表现                           |
| ----------- | ------------------------ | ---------------------------------- |
| 错误密码    | 输入错误密码登录         | 中文提示，不泄露账号是否存在       |
| 断开后端    | 停止后端后刷新页面       | 明确提示服务不可用，可重试         |
| 请求超时    | 模拟慢接口               | 显示超时提示，不无限转圈           |
| AI Key 错误 | 使用错误 Key 测试        | 显示 Provider 错误，不显示完整 Key |
| AI 空响应   | Provider 返回空内容      | 任务失败并说明原因，可重试         |
| 重复导入    | 再导入相同学生名单       | 重复学号跳过，不重复创建           |
| 重复点击    | 连续点击保存、创建、发布 | 按钮 loading，不能产生重复数据     |
| 无权限访问  | 直接输入其他角色 URL     | 返回 403 或登录页                  |
| 过期会话    | 清除 Token 后操作        | 跳转登录，不显示错误堆栈           |
| 超时交卷    | 考试结束仍停留答题页     | 自动交卷或明确禁止继续作答         |

### 安全合格标准

- 页面不显示 API Key、数据库密码、Token；
- 浏览器 Local Storage 不保存 AI Key；
- 所有写操作由后端再次校验权限；
- 不能通过修改 URL、请求参数或隐藏按钮越权；
- 重要操作有确认或幂等保护；
- 审计日志能定位操作人、时间、目标对象和结果。

## 20. 学生端考试专注模式专项验收

### 操作步骤

1. 使用学生账号进入一场已到开考时间的考试须知页；
2. 确认页面单独展示“必须全屏作答”提示；
3. 确认提示说明进入答题后需要点击“进入全屏答题”；
4. 进入答题页，检查普通学生导航不显示；
5. 检查顶部左侧只显示考试标题；
6. 检查顶部右侧按“进入全屏 → 已保存 → 考试监考 → 时间数字”排列，时间数字实时更新；
7. 检查答题进度只显示已答题数和剩余题数；
8. 检查试题区与按题型分组的答题卡在首屏可见；
9. 未进入全屏时确认答题控件和保存/交卷按钮不可用；
10. 点击“进入全屏答题”，确认答题控件恢复可用；
11. 退出全屏或切换窗口，确认页面记录安全事件并提示风险；
12. 展开答题卡并增加题目数量，确认题号区域可滚动且“确认交卷”按钮仍完整可见；
13. 点击顶部左侧返回箭头，确认悬浮提示为“返回考试中心”，考试中先出现二次确认，取消后继续答题；
14. 退出全屏后确认试题区和答题卡出现遮罩，遮罩中央显示“请进入全屏答题”；
15. 点击遮罩中的“进入全屏答题”，确认遮罩消失、试题和答题卡恢复可操作；
16. 返回考试须知或刷新页面，确认倒计时和全屏状态逻辑不丢失。

### 合格标准

- 考前须知明确写出“必须全屏作答”；
- 全屏要求说明退出全屏、切屏、失焦会被记录，多次异常可能自动交卷；
- 答题页普通学生导航隐藏，不展示与当前试卷无关的课程、试卷和满分重复信息；
- 倒计时固定在答题页右上角，剩余时间紧张时有 warning/danger 状态；
- 未进入全屏不能编辑答案、保存草稿或交卷；
- 未进入全屏时试题区和答题卡必须被遮罩锁定，不能通过点击底层控件绕过全屏要求；
- 全屏后题目、答题卡和题型分组保持清晰，不发生横向溢出；
- 退出全屏后的安全事件可在教师端审计入口查询；
- 以上检查必须在真实接口环境和浏览器中执行，Mock 只能作为视觉回归补充。

## 24. 认证与错误反馈验收

### 24.1 退出登录

1. 分别进入教师端、学生端和管理端。
2. 点击顶部“退出”。
3. 合格标准：
   - 出现“确认退出登录？”弹窗；
   - 弹窗说明退出后需要重新登录；
   - 点击“继续使用”后仍停留在当前页面；
   - 点击“退出登录”后返回登录页；
   - 点击遮罩不会误触发退出；
   - 即使注销接口暂时失败，本地会话也会被清理。

### 24.2 修改密码

1. 打开 `/auth/change-password`。
2. 确认页面显示“密码规则”卡片。
3. 分别输入少于 8 位、仅字母、仅数字、与当前密码相同的新密码。
4. 合格标准：
   - 页面明确显示至少 8 个字符、字母、数字和不可复用当前密码；
   - 不合规时前端直接提示中文原因，不发起提交；
   - 合规密码提交后进入原定重定向页面；
   - 后端拒绝时页面仍显示中文原因，不展示英文原文。

### 24.3 错误提示

需要故意制造以下场景：错误密码、过期会话、无权限访问、资源不存在、重复操作、服务器错误、AI Provider 连接失败。

合格标准：

- 页面只展示中文、可理解且可行动的提示；
- 不出现 `MM-xxx-xxx`、`Internal server error`、`Unauthorized`、`Forbidden`、堆栈、JSON 或 API Key；
- AI Provider 失败时至少提示检查服务器地址、模型和 API Key；
- 错误提示应能关闭或在下一次操作前自动清理，不阻塞页面继续使用。
